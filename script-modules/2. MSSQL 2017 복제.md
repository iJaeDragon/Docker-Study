1단계. 원본 컨테이너 정지

```bash
docker stop mssql2017
```

데이터 파일이 쓰이는 도중에 복사하면 손상될 수 있으므로, 컨테이너를 완전히 멈춘 뒤 작업합니다. (필수)

---

2단계. 볼륨 데이터를 압축 파일로 백업

```bash
docker run \
  -v mssql2017-data:/data \
  -v "$(pwd)":/backup \
  alpine tar czf /backup/mssql2017-data.tar.gz -C /data .
```

임시로 `alpine`(가벼운 리눅스) 컨테이너를 하나 띄워서, 원본 볼륨과 현재 로컬 폴더를 동시에 마운트한 뒤 볼륨 안 내용을 통째로 압축해서 로컬 폴더에 저장합니다.

| 옵션 | 설명 |
|---|---|
| `-v mssql2017-data:/data` | 옮기고 싶은 원본 볼륨을 컨테이너 안 `/data` 경로에 연결 (`mssql2017-data`는 볼륨명이다.) |
| `-v "$(pwd)":/backup` | 현재 명령어를 실행하는 폴더를 컨테이너 안 `/backup` 경로에 연결 (결과 파일 저장 위치) |
| `alpine` | `tar` 명령을 바로 쓸 수 있는 아주 가벼운 리눅스 이미지 |
| `tar czf /backup/mssql2017-data.tar.gz -C /data .` | `/data`(=볼륨) 안의 모든 파일을 압축해서 `mssql2017-data.tar.gz`로 저장 |

명령이 끝나면 현재 폴더에 `mssql2017-data.tar.gz`가 생성됩니다. 용량에 따라 시간이 걸릴 수 있습니다.

> Windows PowerShell 사용 시 `"$(pwd)"` 대신 `${PWD}`로 바꿔주세요.
> Windows CMD 사용 시 `"$(pwd)"` 대신 `%cd%`로 바꿔주세요.

명령이 끝난 뒤 이 임시 컨테이너는 더 이상 필요 없으므로, 확인 후 정리해줍니다.

```bash
docker ps -a
```

방금 실행한 `alpine` 컨테이너를 찾아서 삭제합니다.

```bash
docker rm <컨테이너ID 또는 이름>
```

---

3단계. 사용 중인 이미지를 tar 파일로 저장 (인터넷이 안 되므로 필수)

```bash
docker save -o mssql2017-image.tar mcr.microsoft.com/mssql/server:2017-latest
```

대상 PC가 인터넷이 안 되는 상황이므로, `docker pull`로 이미지를 새로 받을 수 없습니다. 그래서 현재 PC에 있는 이미지를 파일로 통째로 내보냅니다.

---

4단계. 원본 컨테이너 재시작

```bash
docker start mssql2017
```

백업이 끝났으니 계속 쓰던 원본 컨테이너를 다시 켭니다. (계속 쓸 필요가 없다면 생략 가능)

---

5단계. 파일을 대상 PC로 전송

아래 두 파일을 USB, 외장하드 등 오프라인 방식으로 옮길 PC에 복사합니다. (인터넷이 안 되므로 네트워크 전송 방식은 사용 불가)

```
mssql2017-data.tar.gz     (실제 테이블/데이터가 담긴 백업 파일)
mssql2017-image.tar       (MSSQL 2017 이미지 파일)
```

---

여기부터는 옮긴 PC(대상 PC)에서 진행합니다.

6단계. 이미지 불러오기

```bash
docker load -i mssql2017-image.tar
```

인터넷 없이, 옮겨온 이미지 파일을 그대로 Docker에 등록합니다. 완료되면 아래로 확인 가능합니다.

```bash
docker images
```

`mcr.microsoft.com/mssql/server` 이미지가 목록에 보이면 정상입니다.

---

7단계. 새 볼륨 생성

```bash
docker volume create mssql2017-data
```

대상 PC에 데이터를 담을 빈 볼륨을 하나 만듭니다. 이름은 원본과 동일하게 해도 되고 다르게 지어도 무방합니다. (뒤에서 그 이름으로 마운트만 정확히 하면 됨)

---

8단계. 압축 데이터를 새 볼륨에 풀기

```bash
docker run \
  -v mssql2017-data:/data \
  -v "$(pwd)":/backup \
  alpine tar xzf /backup/mssql2017-data.tar.gz -C /data
```

2단계와 반대 작업입니다. 옮겨온 `mssql2017-data.tar.gz` 파일이 현재 폴더에 있어야 합니다.

| 옵션 | 설명 |
|---|---|
| `-v mssql2017-data:/data` | 새로 만든 빈 볼륨을 `/data`로 연결 |
| `-v "$(pwd)":/backup` | 압축 파일이 있는 현재 폴더를 `/backup`으로 연결 |
| `tar xzf /backup/mssql2017-data.tar.gz -C /data` | 압축을 풀어서(`x`) `/data`(=새 볼륨) 안에 그대로 넣기 |

작업이 끝나면 이 임시 컨테이너도 정리합니다.

```bash
docker ps -a
docker rm <컨테이너ID 또는 이름>
```

---

9단계. 데이터가 채워진 볼륨으로 컨테이너 실행

```bash
docker run -e "ACCEPT_EULA=Y" \
  -e "SA_PASSWORD=YourStrong@Passw0rd" \
  -e "MSSQL_PID=Developer" \
  -p 1433:1433 \
  --name mssql2017 \
  --hostname mssql2017 \
  -v mssql2017-data:/var/opt/mssql \
  -d mcr.microsoft.com/mssql/server:2017-latest
```

| 옵션 | 설명 |
|---|---|
| `ACCEPT_EULA=Y` | 라이선스 동의 (필수) |
| `SA_PASSWORD` | 원본에서 쓰던 것과 동일하게 입력. 실제 계정 정보는 이미 볼륨 데이터 안에 저장되어 있어서, 여기 입력값은 형식상 필요한 값이며 실제 인증은 볼륨 속 데이터 기준으로 동작 |
| `MSSQL_PID=Developer` | 무료 개발용 에디션 (선택사항, 생략 가능하나 명시 권장) |
| `-p 1433:1433` | 로컬 PC 포트 ↔ 컨테이너 포트 매핑. 대상 PC에서 1433이 이미 사용 중이면 `-p 1434:1433`처럼 다른 포트로 변경 가능 (선택사항) |
| `-v mssql2017-data:/var/opt/mssql` | 8단계에서 데이터를 채워넣은 볼륨을 MSSQL 데이터 경로에 연결 (핵심) |

---

10단계. 초기화 대기

```bash
sleep 15
docker logs mssql2017 --tail 20
```

`SQL Server is now ready for client connections` 메시지가 보이면 준비 완료입니다.

---

11단계. 데이터 정상 이관 확인

```bash
docker exec -it mssql2017 /opt/mssql-tools/bin/sqlcmd \
  -S localhost -U sa -P "YourStrong@Passw0rd" \
  -Q "SELECT 1 AS TestResult"
```

기본 접속이 되면, 실제 기존 테이블/데이터가 옮겨졌는지 확인합니다.

```bash
docker exec -it mssql2017 /opt/mssql-tools/bin/sqlcmd \
  -S localhost -U sa -P "YourStrong@Passw0rd" \
  -Q "SELECT name FROM sys.databases"
```

```bash
docker exec -it mssql2017 /opt/mssql-tools/bin/sqlcmd \
  -S localhost -U sa -P "YourStrong@Passw0rd" \
  -Q "USE TestDB; SELECT * FROM dbo.test"
```

원본에서 만들었던 DB 이름, 테이블, 데이터가 그대로 조회되면 이관이 완벽하게 끝난 것입니다.
