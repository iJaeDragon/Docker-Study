# 컨테이너 가상화 기술과 Docker

## 배포 환경의 발전
- **전통적 방식**: Hardware → OS → Application (분리 없이 직접 실행)
- **서버 가상화**: Hardware → Host OS → Hypervisor → VM(독립 OS) → Application
- **컨테이너 가상화**: Hardware → Host OS → Container Runtime → Container(App)

## 서버 가상화 (하이퍼바이저)
- 하이퍼바이저가 **독립된 게스트 OS(VM)**를 통째로 실행
- Type 1(하드웨어 위 직접 구동) / Type 2(호스트 OS 위 프로그램으로 구동)
- **장점**: 완전히 독립적인 별도 OS처럼 사용 가능
- **단점**: 이미지 크기 큼(1GB↑), 기동 느림(수십 초~수 분), 리소스 많이 소모, 공유 시 변환 필요할 수 있음

## 컨테이너 가상화 (Docker)
- 컨테이너 런타임 위에서 **OS 없이** 앱/미들웨어/DB 등을 컨테이너 단위로 실행
- 호스트 리소스를 일부 공유
- **장점**: 적은 리소스로 빠르게 운영 가능

## 이미지(Image)란?
사진이 아니라, OS·미들웨어·서비스를 하나의 파일로 묶어 배포하는 단위

## 하이퍼바이저 vs 컨테이너 비교

| 항목 | 컨테이너 | 하이퍼바이저 |
|---|---|---|
| 기동 시간 | 수 초 | 수십 초~수 분 |
| 이미지 크기 | 작음 (알파인 400MB) | 큼 (1GB 이상) |
| 이식성 | 이미지 그대로 공유 | 변환 필요할 수 있음 |
| 독립성 | 호스트와 일부 자원 공유 | 완전 독립 |

## 네트워크 & 데이터
- **네트워크**: 컨테이너/VM 모두 외부 접속은 호스트 네트워크 경유. 호스트 연계 / 완전 분리 / 컨테이너 간 통신만 허용 등 구성 선택 가능
- **데이터**: 컨테이너는 종료 시 내부 데이터도 소멸될 수 있어, 외부 스토리지를 **마운트**해서 유지하는 게 일반적

## 예시
- **VirtualBox**: 호스트 PC 한 대에 Ubuntu VM 여러 대를 띄워 Kubernetes 클러스터 구성 가능
- **Docker**: 호스트에 Docker 설치 → Docker Engine이 컨테이너들을 기동, 네트워크 그룹별로 통신 격리/연결 가능

## Docker 설치 참고
- 태생이 리눅스 기반 → 리눅스에서 설치가 가장 이상적
- Windows/macOS는 **Docker Desktop** 설치 필요

## 한 줄 정리
> 서버 가상화 = 무겁지만 완전 독립적인 VM 방식 / 컨테이너 가상화 = 가볍고 빠른 애플리케이션 격리 방식, Docker가 대표 구현체
