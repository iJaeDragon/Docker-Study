# 호스트에서 DB 컨테이너 접속하기 (Workbench / Spring Boot)

## 시나리오
- DB는 **컨테이너**로 기동
- 호스트 PC의 **MySQL Workbench/HeidiSQL** 및 **Spring Boot(Java) 애플리케이션**에서 이 컨테이너에 접속

---

## 자주 만나는 오류 1: 포트 충돌
```
docker run -d -p 3306:3306 -e MARIADB_ALLOW_EMPTY_ROOT_PASSWORD=true --name mariadb1 mariadb
```
- 호스트 PC에 **이미 MySQL/MariaDB가 로컬 설치되어 3306번 포트를 쓰고 있으면** 포트 매핑 실패
- 해결책: 호스트 쪽 포트를 다른 번호로 변경
```
docker run -d -p 13306:3306 -e MARIADB_ALLOW_EMPTY_ROOT_PASSWORD=true --name mariadb1 mariadb
```
- 이 경우 컨테이너 내부는 여전히 3306, 호스트에서 접속할 때만 13306 사용

## 자주 만나는 오류 2: 컨테이너 이름 중복
- 포트 충돌로 실행이 실패했던 컨테이너는 **Created 상태로 남아있음** (Start만 실패, 생성은 됨)
- 같은 `--name`으로 다시 실행하면 **이름 충돌 오류** 발생
- 해결: 기존 컨테이너를 삭제(`docker rm`)하거나 이름을 바꿔서 재실행

---

## 접속 시 포트 번호 기준 (헷갈리기 쉬운 부분)
| 접속 주체 | 사용할 포트 |
|---|---|
| **호스트 PC**(Workbench, 로컬 Java 앱 등)에서 접속 | **매핑해둔 호스트 포트** (예: `13306`) |
| **컨테이너 ↔ 컨테이너** 간 접속 | **컨테이너 내부 포트** (예: `3306`, 매핑과 무관) |

> 즉 "누가 접속을 시도하는가"에 따라 포트 번호가 달라진다는 점을 꼭 기억할 것

---

## 1. MySQL Workbench에서 접속
- Host: `localhost`, Port: `13306` (매핑해둔 호스트 포트)
- User: `root`, Password: 없음
- 정상 연결되면 컨테이너 내부 DB에 접근 가능

## 2. 초기 데이터베이스까지 함께 생성하기
```
docker run -d -p 13306:3306 \
  -e MARIADB_ALLOW_EMPTY_ROOT_PASSWORD=true \
  -e MARIADB_DATABASE=mydb \
  --name mariadb1 mariadb
```
- `MARIADB_DATABASE=mydb`: 컨테이너 최초 기동 시 **`mydb`라는 DB를 자동 생성**

## 3. 호스트의 Spring Boot(Java) 앱에서 DB 접속
- 앱의 `application.yml` 등 설정에서 DB 접속 정보 지정
  - 포트: **호스트 포트**(예: `13306`) 사용 — 앱이 호스트 PC에서 실행되기 때문
  - DB명: `mydb`, User: `root`, Password: 없음
- 실행
```
java -jar catalog-service-mariadb-1.0.jar
```
- 정상 실행되면 앱이 DB에 `catalog` 테이블을 생성하고 초기 데이터 3건을 insert
- 브라우저에서 `localhost:8080/catalogs` 접속 시 데이터 확인 가능

---

## 핵심 포인트
> 호스트 PC의 클라이언트나 애플리케이션이 DB 컨테이너에 접속할 때는 **컨테이너 내부 포트가 아니라 호스트에 매핑해둔 포트**를 써야 한다. 포트가 이미 사용 중이면 호스트 쪽 포트 번호만 바꿔서 매핑하면 되고, 실행 실패로 Created 상태로 남은 컨테이너는 이름 충돌을 일으키므로 삭제 후 재실행해야 한다.
