# Docker Network and Storage

## 기본 개념
- 컨테이너는 기본적으로 **격리된(독립된) 네트워크** 환경에서 작동 → 서로 다른 컨테이너끼리는 기본적으로 통신 불가
- 이런 컨테이너들끼리 통신할 수 있게 해주는 것이 **Docker 네트워크**
- 컨테이너마다 가상 이더넷 카드(**veth**)가 할당되고, 이를 통해 독립적인 IP를 가짐

## 네트워크 종류 (4가지)

| 종류 | 범위 | 설명 |
|---|---|---|
| **Bridge** | Single host | 기본 네트워크 방식. 컨테이너마다 독립 IP 할당, 호스트(게이트웨이)를 거쳐 외부와 통신 |
| **Host** | Single host | 컨테이너가 **호스트 PC와 동일한 네트워크 대역** 사용. 포트 매핑 불필요하지만 포트 충돌 위험 있음 |
| **None** | Single host | 네트워크 사용 안 함 (루프백만 가능, 외부와 완전 단절) |
| **Overlay** | Multi host | 여러 대의 Docker 호스트(PC)를 하나의 네트워크로 묶음. Docker Swarm 등 오케스트레이션에서 사용 |

> Bridge/Host/None은 **싱글 호스트 네트워크**, Overlay는 **멀티 호스트 네트워크**로 구분

---

## 1. Bridge 네트워크 (기본값)
- Docker Desktop 설치 시 기본 네트워크 이름: **`docker0`**
- 컨테이너 생성 시 `docker0` 게이트웨이(예: `172.17.0.1`)를 기준으로 IP가 순차 할당됨 (`.2`, `.3`, `.4`...)
- 컨테이너가 외부 인터넷(패키지 다운로드 등)에 접속하려면 **게이트웨이(docker0) → 호스트 PC**를 거쳐야 함
- **같은 네트워크(같은 대역대)**에 속한 컨테이너끼리는 서로 통신 가능
- **다른 네트워크(다른 대역대)**에 속한 컨테이너끼리는 직접 통신 불가 (그림의 `docker0` ↔ `myNetwork` 사례)
  - 필요하면 `network connect`로 한 컨테이너를 다른 네트워크에도 추가 연결 가능 (컨테이너가 IP를 2개 갖게 됨)

## 2. Host 네트워크
- 컨테이너가 호스트 PC와 **완전히 동일한 IP 대역 및 포트**를 사용
- 장점: 포트 포워딩(`-p`) 없이 바로 컨테이너 서비스 이용 가능
- 단점: 호스트에서 이미 쓰고 있는 포트와 **충돌 가능** (예: 호스트에 MySQL 3306이 떠있는데 컨테이너도 3306을 쓰면 충돌 → 기동 실패)

## 3. None 네트워크
- 외부와 완전히 단절, 루프백(loopback) IP만 사용 가능

## 4. Overlay 네트워크
- 여러 대의 물리적 호스트(Docker가 각각 설치된 여러 PC)를 하나의 네트워크처럼 묶어 사용
- 실습하려면 VM 여러 대에 Docker를 각각 설치해야 함
- Docker Swarm 등 컨테이너 오케스트레이션에서 주로 사용 (추후 별도로 다룸)

## 네트워크 관련 명령어

| 명령어 | 설명 |
|---|---|
| `docker network ls` | 네트워크 목록 확인 |
| `docker network inspect [이름]` | 네트워크 상세 정보 확인 (대역대, 포함된 컨테이너 등) |
| `docker network create [이름]` | 새 네트워크 생성 (옵션 없으면 기본값 = bridge) |
| `docker network create --driver [bridge/host/overlay] [이름]` | 드라이버(종류) 지정해서 네트워크 생성 |
| `docker network rm [이름]` | 네트워크 삭제 |
| `docker network connect [네트워크명] [컨테이너]` | 기존 컨테이너를 다른 네트워크에 추가 연결 |
| `docker network disconnect [네트워크명] [컨테이너]` | 네트워크 연결 해제 |
| `docker run --network [네트워크명] ...` | 컨테이너 실행 시 특정 네트워크에 바로 할당 |

## 핵심 포인트
> 컨테이너는 기본적으로 서로 격리돼 있으며, **같은 네트워크(대역대)에 속해야 서로 통신**할 수 있다. 기본값은 `docker0`이라는 bridge 네트워크이며, 필요에 따라 `docker network create`로 별도 네트워크를 만들고 `--network` 옵션이나 `connect` 명령으로 컨테이너를 원하는 네트워크에 연결해서 구성한다.
