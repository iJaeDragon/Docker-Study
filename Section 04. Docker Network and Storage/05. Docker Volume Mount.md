
# Docker 볼륨 실습

## 볼륨 사용 여부에 따른 차이 확인

### 볼륨 없이 실행 → 데이터 사라짐
```
docker run -it ubuntu:16.04 bash
```
- `docker inspect`의 `Mounts` 항목이 **비어있음** (이미지 자체에 볼륨 마운트가 정의되어 있지 않으면 기본적으로 연결 안 됨)
- 컨테이너 안에서 파일을 만들어도, 컨테이너 종료+삭제 시 데이터도 함께 사라짐

### Named Volume 연결 → 데이터 유지
```
docker volume create myVolume
docker run -it -v myVolume:/app/test ubuntu:16.04 bash
```
- `-v [볼륨명]:[컨테이너 내부 경로]`
- 지정한 컨테이너 내부 경로(`/app/test`)가 없으면 **자동 생성**됨
- 이 안에 파일을 만들면 `myVolume`에 저장됨
- 컨테이너를 삭제한 뒤 **같은 볼륨을 다시 연결해서** 재실행하면 이전 파일이 그대로 남아있음
- macOS/Windows에서는 Docker Desktop 특성상 볼륨의 실제 저장 경로(`/var/lib/docker/volumes/...`)에 **호스트에서 직접 접근 불가** (Linux 환경에서는 직접 접근 가능)

### Bind Mount (호스트 디렉토리 직접 지정) → 데이터 유지 + 호스트에서 직접 확인 가능
```
docker run -it -v ./docker_volume_test:/app/test ubuntu:16.04 bash
```
- `.`(현재 디렉토리) 밑에 `docker_volume_test`라는 **호스트 디렉토리를 직접 지정**해서 연결
- named volume과 달리 **호스트 PC에서 파일을 바로 열람/편집 가능**
- 컨테이너 안에서 만든 파일이 호스트에도 즉시 나타나고, 반대로 호스트(VS Code 등)에서 만든 파일도 컨테이너 내부에 바로 반영됨
- 소스코드 개발, 프로그래밍 작업에 특히 유용

## 볼륨 상세 정보 확인
```
docker inspect [컨테이너]   # Mounts 항목 확인
```
- `Source`: 호스트 PC 쪽 볼륨 저장 위치
- `Destination`: 컨테이너 내부에서 연결된 경로
- 여러 컨테이너가 있을 때, 어떤 볼륨이 어떤 컨테이너와 연결되어 있는지 `Source`/`Destination`으로 파악 가능

## 볼륨 정리 시 주의사항
```
docker volume rm [볼륨명]
```
- 현재 어떤 컨테이너와 **연결되어(사용 중인) 볼륨은 삭제 불가** (오류 발생, 어떤 컨테이너가 쓰는지 메시지로 안내됨)
- 컨테이너를 삭제해도 **볼륨은 자동으로 삭제되지 않고 남아있음** → 불필요한 볼륨은 직접 `rm`으로 정리해야 함

## 실전: DB 컨테이너 데이터 영속성 테스트

### 1. 볼륨 없이 DB 재생성 시 → 데이터 유실
- 볼륨 마운트 없이 DB 컨테이너를 삭제 후 재생성하면 **새로운(빈) 볼륨이 자동 생성**됨 → 기존 테이블/데이터 없음

### 2. 볼륨을 지정해서 DB 실행 → 데이터 유지
```
docker run -d --name mydb -v myDBVolume:/var/lib/mysql \
  -e MARIADB_ALLOW_EMPTY_ROOT_PASSWORD=true mariadb
```
- MariaDB/MySQL 컨테이너는 데이터를 `/var/lib/mysql` 내부에 저장 → 이 경로를 볼륨과 연결해야 함
- 컨테이너를 **완전히 삭제(`stop` + `rm`)한 뒤**, 같은 볼륨(`myDBVolume`)을 지정해서 다시 실행하면
  - 이전에 만들었던 테이블/데이터가 새 컨테이너에서도 그대로 조회됨
  - 워크벤치 등 클라이언트로 접속해도 기존 테이블이 남아있는 것을 확인 가능

## 핵심 포인트
> 볼륨을 연결하지 않으면 컨테이너 삭제 시 데이터도 사라진다. **Named volume**(`-v 볼륨명:경로`)은 Docker가 관리하는 저장 공간을 쓰고, **Bind mount**(`-v 호스트경로:경로`)는 호스트의 특정 폴더를 직접 연결해 파일을 바로 확인/편집할 수 있다. DB처럼 데이터가 중요한 컨테이너는 반드시 볼륨을 연결해서 실행해야 컨테이너를 삭제·재생성해도 데이터를 이어서 사용할 수 있다.
