# Docker 네트워크 실습

## 현재 네트워크/컨테이너 확인
```
docker network ls
docker container inspect [컨테이너ID/이름]
```
- 기본적으로 `bridge`, `host`, `none` 3가지 네트워크가 존재
- `docker network ls`로 확인한 네트워크 ID와 `docker container inspect`에서 보이는 네트워크 ID가 **동일하면 같은 네트워크에 속한 것**
- `inspect` 결과 하단에서 컨테이너의 **소속 네트워크, IP 주소**를 확인 가능

## 네트워크 상세 정보 확인
```
docker network inspect bridge
```
- 해당 네트워크에 **어떤 컨테이너들이 포함되어 있는지**(이름, IP) 하단에 표시됨
- 같은 `bridge` 네트워크에 컨테이너가 여러 개면, IP가 `.2`, `.3`, `.4`... 순서로 순차 할당됨

---

## 새 네트워크 생성
```
docker network create --driver bridge myNetwork
```
- 드라이버 옵션(`--driver`)을 생략하면 기본값은 `bridge`
- 생성 직후 `docker network inspect myNetwork`로 확인하면 서브넷 대역대(예: `172.18.0.0/16`)는 있지만 **포함된 컨테이너는 없음**

## 컨테이너를 특정 네트워크에 할당해서 실행
```
docker run -d --network myNetwork --name registry registry:2
```
- `--network` 옵션 없이 실행하면 **기본(bridge) 네트워크**에 할당됨
- `--network myNetwork`를 지정하면 해당 네트워크의 대역대(예: `172.18.0.2`)로 IP가 할당됨

## 서로 다른 네트워크 간 통신 테스트
```
docker run -it ubuntu:16.04       # --network 옵션 없음 → 172.17.x.x (기본 bridge)
```
- `myNetwork`(172.18.x.x)에 있는 registry와 `bridge`(172.17.x.x)에 있는 ubuntu는 **다른 대역대라 통신 불가**
- 컨테이너 내부에서 `ping` 테스트 시 (ping이 기본 설치 안 되어 있으면 설치 필요)
  ```
  apt update && apt install iputils-ping
  ping 172.18.0.2
  ```
  → 응답 없음 (다른 네트워크라 연결 안 됨)

## 같은 네트워크로 묶어서 실행 → 통신 성공
```
docker run -it --network myNetwork ubuntu:16.04
```
- 이번엔 ubuntu도 `myNetwork`(172.18.x.x)에 할당됨
- 같은 네트워크가 되었으므로 `ping 172.18.0.2` 시 **정상 응답**

---

## 이미 실행 중인 컨테이너에 네트워크 추가하기
```
docker network connect myNetwork MyNode
```
- 처음 실행할 때 `--network`를 지정하지 않았어도, **나중에 `connect`로 다른 네트워크에 추가 연결 가능**
- `docker container inspect MyNode`로 확인하면 **네트워크 정보가 2개**(bridge + myNetwork) 나타나며, IP도 2개(예: `172.17.0.2`, `172.18.0.4`) 갖게 됨
- `docker network inspect myNetwork`로 확인하면 해당 네트워크에 포함된 컨테이너 목록에 새로 추가됨

---

## 명령어 정리

| 명령어 | 설명 |
|---|---|
| `docker network ls` | 네트워크 목록 확인 |
| `docker network inspect [이름/ID]` | 네트워크 상세 정보(대역대, 포함된 컨테이너) 확인 |
| `docker network create --driver [bridge 등] [이름]` | 새 네트워크 생성 |
| `docker run --network [네트워크명] ...` | 컨테이너 생성 시 특정 네트워크에 바로 할당 |
| `docker network connect [네트워크명] [컨테이너]` | 기존 컨테이너를 다른 네트워크에 추가 연결 |
| `docker network disconnect [네트워크명] [컨테이너]` | 네트워크 연결 해제 |
| `docker container inspect [컨테이너]` | 컨테이너가 속한 네트워크/IP 등 상세 정보 확인 |

## 핵심 포인트
> 같은 네트워크(같은 IP 대역대)에 속한 컨테이너끼리만 서로 통신할 수 있다. `--network` 옵션으로 처음부터 원하는 네트워크에 넣거나, 이미 실행 중인 컨테이너는 `docker network connect`로 나중에 추가 연결할 수 있으며, 이 경우 컨테이너는 여러 네트워크에 동시에 속해 여러 개의 IP를 갖게 된다.
