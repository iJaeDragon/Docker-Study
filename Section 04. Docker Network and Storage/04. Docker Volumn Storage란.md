# Docker 볼륨(Volume) 

## 볼륨이 필요한 이유
- 컨테이너 내부에서 생성된 데이터는 기본적으로 **컨테이너 안에만 존재**
- 컨테이너가 삭제되면 그 안의 데이터도 **함께 삭제**됨 → 새 컨테이너를 띄워도 이전 데이터를 이어받을 수 없음
- 이를 해결하기 위해 컨테이너 외부(호스트 PC, 네트워크 드라이브, AWS S3 등)와 **데이터를 연결(마운트)**하는 개념이 **볼륨(Volume)**

## 저장 위치
- Docker 볼륨은 기본적으로 `/var/lib/docker-volumes` 계열 경로에 저장됨 (Docker Desktop 내부)
- OS(Windows/macOS/Linux)에 따라 실제 저장 경로 확인 방법이 다름 (추후 로깅 시간에 별도 설명)

---

## 볼륨 관련 명령어

| 명령어 | 설명 |
|---|---|
| `docker volume create [볼륨명]` | 새 볼륨 생성 |
| `docker volume ls` | 볼륨 목록 확인 |
| `docker volume inspect [볼륨명]` | 볼륨 상세 정보 확인 |
| `docker volume rm [볼륨명/ID]` | 볼륨 삭제 (더 이상 쓰지 않는 볼륨은 정리 필요) |

> 다른 리소스와 마찬가지로 `docker container ...`, `docker image ...`, `docker network ...`처럼 `docker volume ...`으로 시작하는 명령 체계를 사용

---

## 컨테이너에 볼륨 연결하기
```
docker run -v [볼륨명]:[컨테이너 내부 경로] [이미지명]
```
예시:
```
docker run -v myVolume:/var/lib/mysql --name mydb mariadb
```
- `-v` 옵션 앞부분: 사용할 **볼륨 이름**
- `-v` 옵션 뒷부분(`:` 뒤): **컨테이너 내부의 어떤 경로**를 이 볼륨과 연결할지 지정
- 컨테이너의 모든 디렉토리가 자동으로 저장되는 것이 아니라, **`-v`로 지정한 경로만** 볼륨에 저장됨
- `-v` 옵션은 **여러 번 반복 사용 가능** (여러 디렉토리를 각각 다른 볼륨에 연결 가능)
  - `-p`, `-e`처럼 중복 사용 가능한 옵션이며, `--name`처럼 하나만 지정 가능한 옵션과는 다름

## 핵심 포인트
> 볼륨을 연결하지 않으면 컨테이너 삭제 시 데이터도 함께 사라진다. `docker volume create`로 볼륨을 만들고, 컨테이너 실행 시 `-v 볼륨명:컨테이너경로`로 연결하면, 컨테이너가 삭제되고 새로 생성되어도 이 볼륨을 다시 연결해서 이전 데이터를 이어서 사용할 수 있다.
