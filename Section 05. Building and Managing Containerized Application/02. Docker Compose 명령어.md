# Docker Compose 명령어

Docker Compose 파일을 작성할 때 사용하는 주요 옵션과, 작성한 파일을 실행할 때 사용하는 CLI 명령어를 정리한다.

## 1. Compose 파일 작성 옵션

| 옵션 | 설명 |
|---|---|
| `image` | 컨테이너 실행 시 사용할 이미지를 지정 |
| `build` | 이미지를 지정하는 대신 Dockerfile을 기반으로 이미지를 빌드해서 실행 |
| `command` / `entrypoint` | 컨테이너 내부에서 실행할 명령어 지정 (Dockerfile 설정 방식과 유사) |
| `ports` / `expose` | 컨테이너 포트 설정. 멀티 컨테이너 구성 시 활용 |
| `depends_on` | 서비스 간 의존관계 정의 (아래 [2절](#2-depends_on-주의사항) 참고) |
| `environment` / `env_file` | 환경 변수 직접 지정 또는 외부 환경 설정 파일 지정 |
| `container_name` | 컨테이너 이름 지정 (서비스명과 실제 컨테이너명이 다를 수 있어, 명확히 하려면 별도 지정) |
| `volumes` | 데이터 관리를 위한 볼륨 설정 |

## 2. depends_on 주의사항

Docker Compose는 여러 컨테이너를 **순차적으로 실행하지 않고 병렬로 동시에 실행**한다. 예를 들어 container 4가 container 2를 참조해야 하는 구조라도, 실행 시점에 따라 container 2가 아직 준비되지 않은 상태에서 순간적으로 오류가 발생할 수 있다.

`depends_on`으로 의존관계를 지정하면 실행 순서에 힌트를 줄 수 있지만, **100% 순서를 보장하지는 않는다.** 다만 모든 컨테이너의 기동이 끝난 뒤에는 결국 전체 컨테이너가 정상적으로 사용 가능한 상태가 된다.

## 3. Compose 실행 명령어

| 명령어 | 설명 |
|---|---|
| `docker-compose up` | 컨테이너 생성 및 시작 |
| `docker-compose down` | 컨테이너 및 관련 리소스 삭제 |
| `docker-compose ps` | 실행 중인 컨테이너 목록 확인 |
| `docker-compose logs` | 컨테이너 로그 확인 |
| `docker-compose run` | 생성만 되어 있고 실행되지 않은 컨테이너를 다시 실행 |
| `docker-compose stop` | 컨테이너 중지 (삭제는 아님) |
| `docker-compose rm` | 중지된 컨테이너 삭제 |
| `docker-compose port` | 포트 매핑 정보 확인 |
| `docker-compose config` | 현재까지 작성된 설정 확인 |

> `run`, `stop`, `rm`은 Docker Compose 이전에 순수 `docker` 명령어로 하던 작업과 동일한 개념이다. `down`은 컨테이너 자체와 리소스까지 모두 삭제한다는 점에서 `stop`/`rm`과 구분된다.
