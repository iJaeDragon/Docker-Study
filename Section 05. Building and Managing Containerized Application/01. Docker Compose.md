# Docker Compose 개념 & 실습

## Docker Compose란?
- Docker Desktop 설치 시 **기본 포함**되어 별도 설치 없이 바로 사용 가능
- 여러 컨테이너의 실행/설정을 **하나의 스크립트(yaml) 파일**로 정의하고, 한 번에 실행/관리해주는 도구

## 왜 쓰는가?
| 기존 방식 (`docker run`) | Docker Compose |
|---|---|
| 컨테이너마다 명령어를 각각 실행 (예: 12개면 12번) | 파일 하나로 **여러 컨테이너를 한번에 실행** |
| 네트워크 연결을 `connect`/`--network`로 개별 작업 | 컴포즈 파일 안에서 네트워크 설정을 한번에 처리 |
| 명령어를 못 찾으면 다시 검색/복붙 | 파일로 저장되어 **재사용 및 Git 버전관리** 가능 |
| 컨테이너별 로그를 각각 확인 | **하나의 통합된 로그**로 여러 컨테이너 로그 확인 가능 |

## 파일 구조 (docker-compose.yaml)

```yaml
version: "3.8"
services:
  service-name-1:            # 컨테이너 이름 (유니크해야 함)
    image: mariadb:latest    # 사용할 이미지:태그
    # build: .                # 이미지가 없으면 Dockerfile로 빌드
    command: [...]            # 컨테이너 실행 시 추가 명령/옵션
    environment:               # 환경 변수 (예: DB 루트 패스워드)
      - MARIADB_ROOT_PASSWORD=xxxx
    volumes:                   # 볼륨 마운트
      - myvolume:/var/lib/mysql
    networks:                  # 네트워크 지정
      - mynetwork

  service-name-2:
    image: nginx:latest
    ports:
      - "80:80"

volumes:
  myvolume:

networks:
  mynetwork:
```

| 항목 | 설명 |
|---|---|
| `version` | Compose 파일 문법 버전 (3.1, 3.5, 3.7 등) |
| `services` | 실행할 컨테이너들을 정의하는 핵심 섹션. 각 서비스명이 컨테이너 이름 역할 |
| `image` | 사용할 이미지:태그 (기존 `docker run` 마지막에 쓰던 이미지명과 동일 개념) |
| `build` | 이미지가 없을 때 Dockerfile로 빌드해서 사용 |
| `command` | 컨테이너 실행 시 추가 옵션/명령 |
| `environment` | 환경 변수 (`-e` 옵션과 동일 역할) |
| `volumes` | 볼륨 마운트 (`-v` 옵션과 동일 역할) |
| `networks` | 사용할 네트워크 지정 (`--network` 옵션과 동일 역할) |

> 파일명은 기본적으로 `docker-compose.yaml`을 사용하는 것이 표준. 다른 이름(`docker-compose-test.yaml` 등)을 쓸 경우 실행 시 `-f` 옵션으로 반드시 명시해야 함

## 실행 명령어

| 명령어 | 설명 |
|---|---|
| `docker compose up` | 현재 디렉토리의 `docker-compose.yaml`을 찾아 서비스 전체 실행 |
| `docker compose -f [파일명] up` | 파일명을 다른 이름으로 썼을 때 명시적으로 지정해서 실행 |
| `docker compose -f [파일명] up [서비스명]` | 여러 서비스 중 **특정 서비스만** 실행 |
| `docker compose -f [파일명] ps` | 해당 컴포즈가 관리 중인 컨테이너 목록 확인 (파일 위치에서 실행해야 함) |
| `docker compose -f [파일명] down` | 실행 중인 컨테이너 전체 종료 |

## 실습: Nginx를 Compose로 실행하기

```yaml
version: "3.8"
services:
  my-webserver:
    image: nginx
    ports:
      - "80:80"
```

```
docker compose -f docker-compose1.yaml up
```
- 실행하면 Docker Compose가 **기본 네트워크를 자동 생성**하고 컨테이너를 기동
- 컨테이너 이름은 `[폴더명]-my-webserver-1`처럼 **서비스명 뒤에 번호가 자동으로 붙는 규칙**으로 생성됨 (여러 컨테이너 구분용)
- 브라우저에서 `localhost` 접속 시 Nginx 기본 페이지 확인 가능
- `docker compose ps`는 `docker ps`와 유사하지만 **서비스/컴포즈 단위로 더 명확하게 정리**해서 보여줌
- 종료: `docker compose -f docker-compose1.yaml down`

> macOS Apple Silicon(M1/M2/M3) 환경에서는 이미지가 해당 아키텍처를 지원하지 않을 경우 `platform: linux/amd64` 같은 옵션이 필요할 수 있음 (Windows는 해당 없음)

## 핵심 포인트
> Docker Compose는 `docker run`의 다양한 옵션(이미지, 포트, 볼륨, 네트워크, 환경변수 등)을 yaml 파일 하나로 정의해서, `up`/`down` 명령만으로 여러 컨테이너를 한번에 관리할 수 있게 해주는 도구다.
