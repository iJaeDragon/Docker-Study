# Docker Compose 기본 문법 & 명령어 레퍼런스

> 학습 회차: Docker Compose 옵션 소개 + 실행 명령어
> 목적: `docker run`으로 하던 컨테이너 실행을 하나의 YAML 스크립트로 관리하기 위한 문법 정리.
> 이 문서는 나중에 실제 `docker-compose.yml` 작성할 때 바로 참고하는 용도로 작성.

---

## 1. Compose 파일 기본 뼈대

```yaml
version: "3"          # Compose 파일 문법 버전
services:              # 실행할 컨테이너(서비스) 목록
  서비스명1:
    ...
  서비스명2:
    ...
networks:               # (선택) 서비스들이 공유할 네트워크
  ...
volumes:                # (선택) 명명된 볼륨 정의
  ...
```

- `services:` 아래에 컨테이너 단위로 이름을 붙여 나열한다. 이 이름이 **서비스명**이며, 같은 네트워크 안에서는 이 이름이 곧 호스트명(hostname) 역할을 한다.
- 실제 컨테이너 이름은 기본적으로 `{디렉토리명}_{서비스명}_{번호}` 형태로 자동 생성된다. (직접 지정하려면 `container_name` 사용)

## 2. 서비스별 옵션 상세

### 2.1 image — 사용할 이미지 지정

```yaml
services:
  mydb:
    image: mariadb:latest
```

이미지 레지스트리(Docker Hub 등)에 있는 이미지를 그대로 받아서 실행. 가장 기본적인 방식.

### 2.2 build — Dockerfile로 직접 빌드해서 실행

```yaml
services:
  myapp:
    build: ./myapp        # Dockerfile이 있는 경로
    # 또는 세부 옵션 지정
    build:
      context: ./myapp
      dockerfile: Dockerfile.dev
```

`image` 대신 사용. 지정한 경로의 Dockerfile을 빌드한 뒤 그 결과 이미지로 컨테이너를 실행한다.

### 2.3 command / entrypoint — 컨테이너 내부 실행 명령

```yaml
services:
  myapp:
    image: myapp:1.0
    command: ["npm", "start"]
    # entrypoint: ["/bin/sh", "-c"]
```

Dockerfile의 `CMD` / `ENTRYPOINT`와 동일한 역할을 Compose 레벨에서 재정의할 때 사용.

### 2.4 ports / expose — 포트 매핑

```yaml
services:
  myfrontend:
    ports:
      - "8080:80"     # "호스트포트:컨테이너포트"
    expose:
      - "80"           # 컨테이너 간 통신용, 호스트에는 노출 안 함
```

- `ports`: 호스트 PC에서 접속 가능하도록 포트를 외부로 연다.
- `expose`: 같은 네트워크에 있는 다른 컨테이너끼리만 접근 가능(호스트 PC에는 안 열림). 멀티 컨테이너 구성에서 주로 사용.

### 2.5 depends_on — 서비스 의존관계

```yaml
services:
  mybackend:
    image: my-backend:1.0
    depends_on:
      - mydb
  mydb:
    image: mariadb:latest
```

**중요 — 반드시 기억할 것:**
- Compose는 여러 서비스를 **순차 실행이 아니라 병렬(동시) 실행**한다.
- `depends_on`은 "컨테이너 생성 순서"에 대한 힌트일 뿐, **완전히 준비(ready)된 상태까지 보장하지 않는다.** (예: DB 컨테이너는 떴지만 MySQL 프로세스 초기화가 덜 끝난 상태에서 backend가 연결을 시도 → 순간 오류 가능)
- 다만 **모든 컨테이너 기동이 끝난 시점에는 결국 정상 작동**한다. 순간 에러 로그는 무시해도 되는 경우가 많다.
- 실무에서 이 문제가 반복되면 → 서비스를 나눠서 순차적으로 `up` 하거나(아래 4절 참고), healthcheck + `condition: service_healthy` 조합을 쓰는 방법도 있음(추후 학습 예정).

### 2.6 environment / env_file — 환경 변수

```yaml
services:
  mydb:
    image: mariadb:latest
    environment:
      MYSQL_ROOT_PASSWORD: ""
      MYSQL_DATABASE: mydb
    # 또는 외부 파일로 분리
    env_file:
      - ./db.env
```

- `environment`: yaml 안에 직접 key-value로 작성.
- `env_file`: `.env` 형식의 별도 파일을 지정해서 불러오기. 민감한 값이나 환경별 분리가 필요할 때 유용.

### 2.7 container_name — 컨테이너 이름 고정

```yaml
services:
  mydb:
    image: mariadb:latest
    container_name: my-db-container
```

지정하지 않으면 `{폴더명}_{서비스명}_{번호}` 형태로 자동 생성됨. `docker ps`에서 정확한 이름을 보고 싶을 때 명시적으로 지정.

### 2.8 volumes — 데이터 영속화

```yaml
services:
  mydb:
    image: mariadb:latest
    volumes:
      - ./data:/var/lib/mysql     # 호스트경로:컨테이너경로
```

컨테이너가 삭제되어도 호스트 PC의 `./data` 폴더에 데이터가 남아있어, 다음에 컨테이너를 다시 띄웠을 때 이전 데이터를 그대로 이어서 사용할 수 있다.

## 3. Compose 파일 실행 명령어 전체 정리

| 명령어 | 설명 | 자주 쓰는 옵션 |
|---|---|---|
| `docker-compose up` | 컨테이너 생성 + 시작 | `-d` (백그라운드/detached), `-f <파일명>` (파일 지정), 서비스명 (특정 서비스만) |
| `docker-compose down` | 컨테이너 + 기본 네트워크까지 전부 삭제 | - |
| `docker-compose ps` | Compose 기준 컨테이너 목록/상태 확인 | `-f <파일명>` |
| `docker-compose logs` | 컨테이너 로그 확인 | `-f` (실시간 tail), 서비스명 (특정 서비스만 필터) |
| `docker-compose run` | 생성은 됐지만 실행 안 된 컨테이너를 다시 실행 | - |
| `docker-compose stop` | 컨테이너 중지(삭제 아님, 재시작 가능) | - |
| `docker-compose rm` | 중지된 컨테이너 삭제 | - |
| `docker-compose port` | 포트 매핑 정보 확인 | - |
| `docker-compose config` | 현재 작성된 설정(YAML)이 올바른지 검증 및 출력 | - |

### 실전 사용 예시

```bash
# 파일명을 지정해서 백그라운드로 전체 실행
docker-compose -f docker-compose.yml up -d

# 특정 서비스만 실행
docker-compose -f docker-compose.yml up mydb

# 컨테이너 상태 확인
docker-compose -f docker-compose.yml ps

# 전체 로그 확인
docker-compose -f docker-compose.yml logs

# 특정 서비스 로그만 확인
docker-compose -f docker-compose.yml logs mybackend

# 중지만 (재시작 가능한 상태로 남김)
docker-compose -f docker-compose.yml stop

# 완전 삭제 (컨테이너 + 기본 네트워크)
docker-compose -f docker-compose.yml down
```

> `run`, `stop`, `rm`은 개념적으로 순수 `docker` 명령어(`docker run`, `docker stop`, `docker rm`)와 동일한 작업을 Compose 레벨에서 수행하는 것.
> `down`은 `stop` + `rm` + (기본 생성된) 네트워크 삭제까지 한번에 처리한다는 점에서 다름.

## 4. 체크리스트 (실전에서 헷갈릴 때 다시 보기)

- [ ] 여러 컨테이너를 동시에 띄우는데 특정 서비스가 먼저 준비돼야 한다 → `depends_on` 걸어두되, 100% 보장 아님을 기억
- [ ] 컨테이너 삭제 후에도 데이터를 유지하고 싶다 → `volumes`로 호스트 경로 마운트
- [ ] 같은 값을 재사용/분리 관리하고 싶다 → `environment` 대신 `env_file`
- [ ] `docker ps`에서 보이는 이름이 예상과 다르다 → 폴더명 기반 자동 네이밍이므로 `container_name`으로 고정 가능
- [ ] 컨테이너 내부 포트만 다른 컨테이너에 열고 싶다(호스트에는 안 열고) → `ports` 대신 `expose`
