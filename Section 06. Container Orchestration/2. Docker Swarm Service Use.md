# Docker Swarm Service 배포 & 스케일링 레퍼런스

---

## 0. 원칙 — Service 관련 명령은 항상 Manager에서

`docker service` 관련 명령은 **Worker 노드가 아니라 반드시 Manager 노드에서 실행**한다. Manager가 명령을 받아서 각 Worker에게 컨테이너를 배포/삭제하도록 지시하는 구조.

---

## 1. Service란

여러 컨테이너로 구성된 애플리케이션을 클러스터 레벨에서 제어하기 위한 단위. `docker service` 명령으로 생성/관리하며, 가장 큰 장점은 **스케일링(replica 개수 조절)을 지원**한다는 것.

---

## 2. 명령어 레퍼런스

| 명령어 | 설명 |
|---|---|
| `docker service create [옵션] <이미지>` | 서비스 생성 |
| `docker service ls` | 서비스 목록 확인 (이름, replica 현황, 포트 등) |
| `docker service ps <서비스명>` | 해당 서비스의 각 컨테이너가 **어느 노드에 배포됐는지** 확인 |
| `docker service scale <서비스명>=<개수>` | replica(복제) 개수 조정 |
| `docker service rm <서비스명>` | 서비스 삭제 (관련 컨테이너 전부 정리됨) |

### `docker service create` 주요 옵션

| 옵션 | 설명 | 예시 |
|---|---|---|
| `--name` | 서비스 이름 지정 | `--name mynginx` |
| `-p`, `--publish` | 포트 매핑 (호스트:컨테이너) | `-p 80:80` |
| `--replicas` | 처음 생성할 복제본(컨테이너) 개수 | `--replicas 1` |

---

## 3. 실습: mynginx 서비스 생성

```bash
# Manager 노드에서 실행
docker service create \
  --replicas 1 \
  --publish 80:80 \
  --name mynginx \
  nginx:latest
```

- 이미지가 로컬에 없으면 자동으로 pull 해온 뒤 서비스 생성.
- `--replicas 1`이므로 컨테이너 1개만 생성되지만, **어느 노드(manager/worker1/worker2)에 배포될지는 지정하지 않는 한 Manager가 알아서 결정** (특정 조건을 안 주면 랜덤/자동 배치).

### 확인

```bash
docker service ls
# NAME       REPLICAS   IMAGE          PORTS
# mynginx    1/1        nginx:latest   *:80->80/tcp

docker service ps mynginx
# 어떤 노드(NODE 컬럼)에 배포됐는지 확인 가능
```

각 워커 노드에 직접 접속해서 `docker ps`로 확인해보면, 실제로 컨테이너가 떠 있는 노드에서만 프로세스가 보이고 나머지 노드에는 아무것도 안 보인다.

---

## 4. 스케일링 (Scale Out)

```bash
docker service scale mynginx=3
```

- 기존 1개였던 컨테이너가 **총 3개**(`mynginx.1`, `mynginx.2`, `mynginx.3`)로 늘어나며, Manager가 이 3개를 **클러스터 전체 노드(manager + worker1 + worker2)에 분산 배치**한다.
- 반드시 노드마다 1개씩 균등하게 배치되는 것은 아니며, 한 노드에 여러 개가 몰릴 수도 있다. 배치 결정은 Manager가 담당.

```bash
docker service ls          # REPLICAS: 3/3 확인
docker service ps mynginx  # 각 replica가 어느 노드에 있는지 확인
```

## 5. 자가 복구 (Self-Healing) 확인

Swarm의 핵심 특징: **지정한 replica 개수를 항상 유지하려고 시도**한다.

### 실습: 노드 중 하나를 강제로 죽여보기

```bash
# 해당 컨테이너가 떠 있는 노드에서 실행
docker stop <해당 컨테이너 ID>
```

컨테이너를 강제 종료해도 잠시 후(수 초 내) 그 노드 혹은 사용 가능한 다른 노드에 **새 컨테이너가 자동으로 다시 생성**된다. 죽은 컨테이너는 삭제된 채로 남고, 새 컨테이너가 replica 수(3개)를 다시 채운다.

```bash
docker service ps mynginx   # 이전 컨테이너는 Shutdown 상태, 새 컨테이너가 Running으로 추가된 것을 확인
```

> 이것이 오케스트레이션 도구의 핵심 가치 — 장애 발생 시 사람이 개입하지 않아도 지정된 상태(replica 수)를 자동으로 복구한다.

---

## 6. 스케일 인 (Scale Down) & 서비스 삭제

```bash
# 3개 → 1개로 축소
docker service scale mynginx=1

# 서비스 자체를 완전히 삭제 (관련 컨테이너 전부 정리)
docker service rm mynginx

# 확인 — 목록이 비어 있어야 정상
docker service ls
docker service ps mynginx   # 에러 또는 빈 결과
```

---

## 7. 핵심 정리 (체크리스트)

- [ ] Service 관련 명령은 **Manager 노드**에서만 실행
- [ ] `docker service create --replicas <N> --publish <호스트포트>:<컨테이너포트> --name <이름> <이미지>` 로 생성
- [ ] `docker service ls` = 서비스 단위 요약, `docker service ps <이름>` = 개별 컨테이너가 배포된 노드까지 상세 확인
- [ ] `docker service scale <이름>=<N>` 으로 언제든 replica 개수 조정 가능 (스케일 아웃/인)
- [ ] 컨테이너 하나가 죽어도 Swarm이 **자동으로 replica 수를 다시 채워준다** (self-healing)
- [ ] 완전히 정리하려면 `docker service rm <이름>`
