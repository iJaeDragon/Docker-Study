# Docker Swarm Rollback 레퍼런스

---

## 1. Rollback이란

말 그대로 **현재 상태를 이전 상태로 되돌리는** 기능. 새 버전을 배포했는데 문제가 생겼을 때, 직전에 정상 작동하던 버전으로 서비스를 되돌릴 때 사용한다. Rolling Update와 사용 방식(옵션 구조)이 거의 동일하고, "update" 대신 "rollback"이라는 용어를 쓴다고 이해하면 된다.

---

## 2. 핵심 옵션

서비스를 **생성할 때 미리** 롤백 정책을 지정해둘 수 있다.

| 옵션 | 설명 |
|---|---|
| `--rollback-delay` | 롤백 시 배치 간 대기 시간 (예: `10s`) |
| `--rollback-parallelism` | 한 번에 몇 개씩 롤백할지 (예: `1` → 하나씩) |
| `--rollback-failure-action` | 롤백 도중 실패 시 동작. `pause`(중단하고 대기) 등 |

```bash
# 예시: Redis 서비스를 만들면서 롤백 정책도 함께 지정
docker service create \
  --name redis \
  --replicas 4 \
  --rollback-delay 10s \
  --rollback-parallelism 1 \
  --rollback-failure-action pause \
  redis:7.0.3
```

---

## 3. Rollback 명령어

| 명령어 | 설명 |
|---|---|
| `docker service update --rollback <서비스명>` | 서비스를 **직전 스펙**으로 되돌림 |
| `docker service ps <서비스명>` | 롤백 진행 상황(Shutdown/Running, 이미지 버전, 시간) 확인 |

> **주의**: 롤백을 하려면 그 전에 **최소 1번 이상 `update`를 실행한 이력**이 있어야 한다. 처음 생성한 상태에서 바로 롤백을 시도하면 되돌아갈 "이전 상태"가 없어서 오류 발생.

---

## 4. 실습 전체 흐름

```bash
# 1) 서비스 생성 (nginx:latest, replica 4개)
docker service create --name myweb3 --replicas 4 nginx:latest

# 2) 상태 확인
docker service ls
docker service ps myweb3        # 전부 nginx:latest

# 3) 1차 업데이트 (latest → 1.24)
docker service update --image nginx:1.24 myweb3
docker service ps myweb3        # 전부 nginx:1.24로 변경 확인

# 4) 2차 업데이트 (1.24 → 1.25)
docker service update --image nginx:1.25 myweb3
docker service ps myweb3        # 전부 nginx:1.25로 변경 확인

# 5) 롤백 실행 (1.25 → 직전 상태인 1.24로 복귀)
docker service update --rollback myweb3
docker service ps myweb3        # nginx:1.24로 되돌아온 것 확인
```

`docker inspect <컨테이너ID> | grep -i created` (Windows는 `findstr`)로 실제 컨테이너가 언제 새로 생성됐는지 타임스탬프를 비교해보면, 하나씩 10초 간격으로 순차 롤백되는 것을 직접 확인할 수 있다.

---

## 5. ⚠️ 중요한 제약 — Rollback은 "직전 상태"와만 토글된다

가장 헷갈리기 쉬운 부분. Swarm은 서비스의 **전체 배포 히스토리를 스택처럼 쌓아두지 않는다.** 오직 "현재 스펙"과 "바로 직전 스펙" **두 개만** 기억한다.

<img width="765" height="367" alt="image" src="https://github.com/user-attachments/assets/5e34d336-af82-4ba2-a647-4f63db80509c" />

```bash
# 버전 흐름: latest → 1.24 → 1.25 (현재)

docker service update --rollback myweb3   # 1.25 → 1.24로 이동 (정상)

docker service update --rollback myweb3   # 1.24 → 1.25로 다시 이동 (❌ 1.23이나 latest로 못 감!)
```

- 롤백을 반복 실행하면 **직전 두 상태 사이를 왔다 갔다(toggle)** 할 뿐, 그보다 이전 버전(`latest`, `1.23` 등)으로는 갈 수 없다.
- "몇 단계 전으로 가고 싶다"는 식의 숫자 지정은 **지원하지 않는다.** 실제로 시도하면 `invalid syntax` 오류가 발생한다.
- 이는 `docker service update --help`의 `--rollback` 옵션 설명에서도 확인 가능 — **`previous`만 지정 가능**하고 여러 단계 이전으로 가는 옵션은 없다.

**실무 시사점**: 두 단계 이상 이전 버전으로 되돌려야 한다면, `rollback`을 쓰는 게 아니라 `docker service update --image <원하는 버전>`으로 **직접 원하는 버전을 명시해서 업데이트**해야 한다.

```bash
# 두 단계 전(예: latest)으로 명확히 되돌리고 싶을 때는 rollback이 아니라 update로
docker service update --image nginx:latest myweb3
```

## 6. 핵심 정리 (체크리스트)

- [ ] Rollback은 **update 이력이 최소 1번**은 있어야 사용 가능
- [ ] `docker service update --rollback <서비스명>`으로 직전 상태로 복귀
- [ ] 롤백도 Rolling Update처럼 `--rollback-delay` / `--rollback-parallelism`으로 속도·동시 개수 조절 가능 (서비스 생성 시 사전 설정)
- [ ] **핵심 함정**: rollback은 히스토리 전체가 아니라 **직전 상태 1개와만 토글** — 반복 실행하면 최근 두 버전 사이를 왔다 갔다 할 뿐
- [ ] 여러 단계 이전 버전으로 가려면 `rollback`이 아니라 `update --image <특정 버전>`을 사용
