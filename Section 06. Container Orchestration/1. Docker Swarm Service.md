# Docker Swarm 클러스터 구성 실습 (DinD 방식)

> 학습 회차: Docker Swarm 클러스터 구성 — Manager/Worker 개념, PC 1대로 멀티 호스트를 시뮬레이션하는 DinD(Docker in Docker) 방식, `swarm init`/`swarm join` 실습
> 목적: 나중에 실제로 Swarm 클러스터를 다시 구성할 때 명령어를 그대로 참고할 수 있는 수준으로 정리.

---

## 1. Manager Node / Worker Node 개념

| 노드 | 역할 |
|---|---|
| **Manager Node** | 클러스터를 초기화하는 노드. 클러스터 관리(스케줄링, 상태 관리) 담당 |
| **Worker Node** | Manager에 등록되어 실제 컨테이너를 배포/운영하는 노드 |

- 노드 역할은 미리 정해져 있는 게 아니라, **어느 PC에서 `docker swarm init`을 실행하느냐**에 따라 그 PC가 Manager가 된다. (3대의 PC가 있을 때 3번 PC에서 init 하면 3번이 Manager)
- 모든 노드는 사전에 **Docker가 설치된 동일한 환경**이어야 한다.

### 핵심 명령어

| 명령어 | 위치 | 역할 |
|---|---|---|
| `docker swarm init` | Manager가 될 노드 | Swarm 모드 활성화(클러스터 초기화). 실행 시 **Join Token**이 발급됨 |
| `docker swarm join --token <TOKEN> <MANAGER_IP>:<PORT>` | Worker가 될 노드 | 발급받은 토큰으로 Manager에 접속 → Worker Node로 등록 |
| `docker swarm leave` | 아무 노드 | 해당 노드를 Swarm 클러스터에서 제거 |
| `docker node ls` | Manager | 클러스터에 속한 전체 노드 목록/상태 확인 (Leader 표시로 Manager 구분) |

Swarm 통신에 사용되는 포트 (직접 사용하는 포트는 아니지만 자동으로 매핑됨, 참고용):

| 포트 | 용도 |
|---|---|
| `2377` | 클러스터 매니지먼트 통신 |
| `7946` | 노드 간 통신 |
| `4789` | 오버레이 네트워크 |

## 2. 왜 DinD(Docker in Docker) 방식을 쓰는가

Swarm 클러스터를 제대로 구성하려면 **PC(호스트)가 여러 대** 있어야 하는데, 실습 환경상 대부분 PC 1대뿐이다. 두 가지 대안이 있다.

| 방법 | 설명 |
|---|---|
| **① VM(가상머신)** | VirtualBox/VMware 같은 하이퍼바이저를 설치 → 여러 개의 게스트 OS(VM)를 생성해서 각각을 Docker Host로 사용 |
| **② DinD (Docker in Docker)** | 이미 설치된 Docker(Docker Desktop) 위에 **Linux 컨테이너를 여러 개 띄우고, 그 컨테이너 내부에 다시 Docker를 설치**해서 각각을 독립된 Docker Host처럼 사용 |

이번 실습은 **② DinD 방식**을 사용한다 (참고로 반대 개념인 "Docker Out of Docker(DooD)"는 컨테이너 밖에서 호스트의 Docker 소켓을 그대로 연결해 쓰는 방식으로, DinD와는 다름).

## 3. DinD 이미지로 노드 컨테이너 띄우기

강사가 제공한 DinD 이미지(Docker Hub, 계정별 제공)를 사용. OS별로 이미지가 다르므로 본인 환경에 맞는 태그 선택 필요 (Windows 10 / Windows 11 / macOS Intel / macOS Apple Silicon(M1) / Linux 용 별도 제공).

### 예시: Manager 노드 실행

```bash
docker run -d --privileged --name manager \
  -p 10022:22 \
  -p 8088:8080 \
  <계정>/docker-server:m1        # 본인 환경에 맞는 태그로 교체 (예: intel, ubuntu22.04, no-iptables 등)
```

### 예시: Worker 노드 실행 (포트를 겹치지 않게 변경)

```bash
# worker1
docker run -d --privileged --name worker1 \
  -p 20022:22 \
  -p 8082:8080 \
  <계정>/docker-server:m1

# worker2
docker run -d --privileged --name worker2 \
  -p 30022:22 \
  -p 8083:8080 \
  <계정>/docker-server:m1
```

> **포트 규칙**: SSH용 컨테이너 내부 22번 포트를 호스트의 서로 다른 포트(10022 / 20022 / 30022)로 매핑. 앱 포트(8080)도 컨테이너마다 다른 호스트 포트(8088 / 8082 / 8083)로 매핑해서 충돌 방지.

### 실행 후 반드시 확인할 것 — 컨테이너 로그

```bash
docker logs manager
```

`OK, OK, OK` 형태로 OpenSSH 등 초기화 로그가 보이면 정상. 일부 `Fail`은 무시 가능하지만, SSH 관련 실패가 계속되면 다른 태그의 이미지를 시도해야 할 수 있음.

## 4. 컨테이너(노드)에 접속하는 두 가지 방법

### 방법 A — `docker exec`

```bash
docker exec -it manager bash
```

### 방법 B — SSH

```bash
ssh root@127.0.0.1 -p 10022
# 비밀번호: P@ssw0rd!  (실습용 예시 계정)
```

**흔한 오류: SSH known_hosts 충돌**
같은 `127.0.0.1`에 다른 포트로 재접속하면 SSH가 "호스트가 바뀌었다"고 오류를 낼 수 있다. 해결:

```bash
cd ~/.ssh
vi known_hosts     # 또는 code known_hosts (VS Code)
# 기존 항목 전체 삭제 후 저장 (:wq)
```

이후 다시 접속하면 최초 접속 확인(yes) → 비밀번호 입력 순서로 정상 접속됨.

## 5. 컨테이너 내부에서 Docker 데몬 기동

DinD 컨테이너에 접속한 직후에는 **내부 Docker 데몬이 꺼져 있는 상태**다. 반드시 아래 순서로 켜야 한다.

```bash
docker version                # 이 시점엔 Client만 보이고 "Cannot connect to the Docker daemon" 에러 발생

systemctl enable docker       # 부팅 시 자동 실행 등록
systemctl start docker        # Docker 서비스 시작
systemctl status docker       # 정상 작동 확인 (active (running) 확인)

docker version                # Client + Server(Community) 버전 모두 표시되면 성공
```

> **모든 노드(manager, worker1, worker2)에서 각각 위 3단계를 실행해야 한다.** 하나라도 빠뜨리면 해당 노드에서 `docker swarm` 명령이 실패한다.

## 6. Swarm 클러스터 구성 (init & join)

### 6.1 Manager에서 초기화

```bash
docker swarm init
```

성공하면 아래와 같은 형태의 join 명령어가 출력에 포함되어 나온다 (토큰은 매번 다름).

```
docker swarm join --token SWMTKN-1-xxxxxxxxxxxx 172.17.0.2:2377
```

이 명령어를 그대로 복사해둔다.

### 6.2 각 Worker에서 join

```bash
# worker1, worker2 컨테이너 안에서 각각 실행
docker swarm join --token SWMTKN-1-xxxxxxxxxxxx 172.17.0.2:2377
```

`This node joined a swarm as a worker.` 메시지가 뜨면 성공.

### 6.3 Manager에서 전체 노드 확인

```bash
docker node ls
```

출력 예시(개념):

| ID | HOSTNAME | STATUS | AVAILABILITY | MANAGER STATUS |
|---|---|---|---|---|
| xxxx *(현재 노드 표시)* | manager 컨테이너ID | Ready | Active | **Leader** |
| yyyy | worker1 컨테이너ID | Ready | Active | - |
| zzzz | worker2 컨테이너ID | Ready | Active | - |

`Leader`로 표시되는 노드가 Manager. 나머지 두 개가 정상적으로 Worker로 등록되어 있으면 클러스터 구성 완료.

## 7. 전체 흐름 요약 (체크리스트)

- [ ] 본인 OS/CPU에 맞는 DinD 이미지 태그 확인 (Windows10/11, macOS Intel/M1, Linux)
- [ ] `docker run`으로 manager, worker1, worker2 컨테이너 실행 (포트 충돌 없이 각각 다르게 매핑)
- [ ] `docker logs <컨테이너명>`으로 초기화 정상 여부 확인
- [ ] `docker exec -it` 또는 `ssh`로 각 컨테이너 접속
- [ ] (SSH 시) known_hosts 충돌 나면 삭제 후 재접속
- [ ] 모든 노드에서 `systemctl enable docker` → `systemctl start docker` → `systemctl status docker` 확인
- [ ] Manager에서 `docker swarm init` 실행 → join 토큰 확보
- [ ] 각 Worker에서 `docker swarm join --token ...` 실행
- [ ] Manager에서 `docker node ls`로 전체 노드(Leader + Worker들) 등록 확인
