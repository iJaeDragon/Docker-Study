# Docker Swarm Rolling Update (무중단 배포) 레퍼런스

> 학습 회차: 서비스 업데이트 시 다운타임 없이 배포하는 Rolling Update, `--replicas` / `--update-delay` / `--update-parallelism` 옵션, 실습 결과 확인
> 목적: 나중에 서비스 배포/업데이트 전략을 짤 때 옵션과 명령어를 바로 참고.

---

## 1. 무중단 배포(Rolling Update)란

새 버전을 배포할 때 서비스를 완전히 내렸다가 다시 올리는 것이 아니라, **다운타임 없이** 순차적으로 컨테이너를 교체하는 배포 방식.

- 서비스(replica)가 **1개뿐이면** 무중단 배포 자체가 불가능 — 내렸다가 다시 올릴 수밖에 없음.
- 서비스가 **2개 이상**일 때부터 의미가 있음. 로드밸런서가 요청을 분산하는 상태에서, 한 번에 전부가 아니라 **일부씩 순서대로** 업데이트한다.

### 동작 흐름 (서버 A, B 두 대 예시)

<img width="698" height="232" alt="image" src="https://github.com/user-attachments/assets/6114bda1-c255-446b-bc58-1fc1e7e732d4" />

1. **1단계**: 서버 A는 기존 버전(v1.0)으로 정상 서비스 중, 서버 B는 배포 진행 중(요청 안 받음)
2. **2단계**: 서버 B 배포 완료 → 이제 서버 B가 요청을 받고, 서버 A가 배포 시작
3. **3단계**: 서버 A도 완료 → 둘 다 새 버전(v1.1)으로 정상 서비스, **서비스 중단 없이** 배포 완료

---

## 2. 핵심 옵션 2가지

| 옵션 | 설명 |
|---|---|
| `--update-delay` | 업데이트 배치 간 **대기 시간** (예: `10s` → 10초 간격으로 다음 배치 진행) |
| `--update-parallelism` | 한 번에 **동시에 업데이트할 개수** (예: `2` → 2개씩 묶어서 순차 업데이트) |

> **명령은 항상 Manager 노드에서 실행**한다. `docker service create`/`docker service update` 둘 다 마찬가지.

옵션을 지정하지 않으면 **기본값은 update-delay 10초, 한 번에 1개씩** 업데이트된다.

---

## 3. 명령어 레퍼런스

| 명령어 | 설명 |
|---|---|
| `docker service create --name <이름> --replicas <N> <이미지>` | 서비스 생성 |
| `docker service update --image <새이미지> <서비스명>` | 이미지를 교체해 롤링 업데이트 수행 |
| `docker service update --update-delay <시간> --update-parallelism <N> --image <새이미지> <서비스명>` | 딜레이/병렬 개수를 지정하며 업데이트 |
| `docker service ls` | 서비스 목록/replica 현황 |
| `docker service ps <서비스명>` | 각 replica가 어느 노드에서 어떤 이미지로 실행 중인지 상세 확인 (Shutdown/Running 이력 포함) |

## 4. 실습 1 — 기본 Rolling Update (딜레이/병렬 옵션 미지정 → 기본값 10초, 1개씩)

```bash
# Manager 노드에서 실행
# 1) 서비스 생성 (replica 3개 → manager/worker1/worker2에 하나씩 분산되는 경우가 일반적)
docker service create --name myweb --replicas 3 nginx:latest

# 2) 현재 상태 확인
docker service ls
docker service ps myweb        # 3개 모두 nginx:latest로 Running 확인

# 3) 롤링 업데이트 — 이미지를 이전 버전(nginx:1.24)으로 교체
docker service update --image nginx:1.24 myweb

# 4) 진행 상황 확인
docker service ps myweb
```

**관찰 포인트**
- 처음 업데이트 시 로컬에 `nginx:1.24` 이미지가 없으면 pull 시간이 걸림 (이후엔 캐시되어 빠름).
- `docker service ps myweb`로 보면 기존 컨테이너들이 `Shutdown` 상태로, 새 컨테이너가 `Running`으로 순차 교체됨.
- 기본 딜레이(10초) 간격으로 **하나씩** 순차 교체되는 것을 타임스탬프(예: "53초 전", "43초 전", "34초 전")로 확인 가능 — 약 10초 간격으로 하나씩 바뀜.

---

## 5. 실습 2 — 딜레이/병렬 옵션 명시 (replicas 4, 2개씩 동시에, 10초 간격)

```bash
# 1) 새 서비스 생성 (replica 4개)
docker service create --name myweb2 --replicas 4 nginx:latest

# 2) 배포 위치 확인 (한 노드에 2개가 몰릴 수도 있음 — 3개 노드에 4개를 나누는 경우)
docker service ps myweb2

# 3) 롤링 업데이트 — 10초 간격, 2개씩 동시 업데이트
docker service update \
  --update-delay 10s \
  --update-parallelism 2 \
  --image nginx:1.24 \
  myweb2

# 4) 진행 상황 확인
docker service ps myweb2
```

**관찰 포인트**
- replica 4개 중 **2개가 동시에** 먼저 교체되고, 약 10초 뒤 나머지 2개가 동시에 교체됨.
- `docker service ps myweb2`의 타임스탬프로 "21초 전 2개 완료 → 약 10초 뒤 3,4번째 완료" 패턴 확인 가능.

## 6. 정리 체크리스트

- [ ] 무중단 배포는 **replica 2개 이상**일 때만 의미가 있다 (1개면 다운타임 불가피)
- [ ] `docker service create`/`update` 명령은 **Manager 노드**에서 실행
- [ ] `--update-delay`로 배치 간 대기시간, `--update-parallelism`으로 한 번에 업데이트할 개수 조절
- [ ] 옵션을 안 주면 기본값(10초 간격, 1개씩)으로 동작
- [ ] `docker service ps <이름>`으로 실제 교체 순서·시간 간격·노드 위치를 직접 확인하며 검증하는 습관
