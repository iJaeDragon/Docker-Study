# Docker 컨테이너 격리(Isolation) 보안 레퍼런스


## 1. 컨테이너 격리(Isolation)란

컨테이너는 기본적으로 다른 컨테이너·호스트와 **격리된 상태**로 실행된다. 이 격리 덕분에:

- 무단 접근을 방지하고
- 문제가 하나의 컨테이너에서 발생해도 다른 컨테이너/호스트로 번지는 위험을 최소화

컨테이너는 마치 각자가 하나의 작은 VM처럼 동작하며, **네트워크(IP 대역, 포트)까지 완전히 분리**할 수도 있고, 원하면 여러 컨테이너를 묶어서 같은 네트워크를 공유하게 만들 수도 있다.

이 격리는 **네임스페이스(Namespace)** 단위로 이루어진다 — 프로세스, 네트워킹, 파일 시스템이 각각 독립적으로 분리된다.

---

## 2. cgroups로 리소스 제한

**cgroups**(Control Groups)를 이용하면 컨테이너가 사용할 수 있는 **CPU/메모리 리소스를 제한**할 수 있다. 지정하지 않으면 기본값이 적용되지만, 명시적으로 제한을 걸어두면 하나의 컨테이너가 호스트 리소스를 무한정 잠식하는 것을 막을 수 있다.

```bash
docker run -it \
  --cpus="0.5" \
  --memory="512m" \
  <이미지명>
```

- `--cpus="0.5"`: CPU 0.5코어만 사용
- `--memory="512m"`: 메모리 512MB로 제한

---

## 3. 사용자 권한 낮추기 (User Namespace Remapping)

- 컨테이너 내부의 사용자 ID를 호스트 PC의 사용자 ID와 어떻게 매핑할지 조절할 수 있다.
- **루트(root) 사용자**는 사실상 모든 것을 할 수 있는 슈퍼유저 권한을 갖는다 — 만약 공격자가 루트 권한을 획득하면 컨테이너 내에서 모든 작업이 가능해진다는 뜻이기도 하다.
- 그래서 컨테이너 실행 시 **루트가 아닌, 권한이 낮은 사용자**로 매핑해서 쓰는 것이 보안 강화 방법 중 하나다.

```bash
# 리눅스에 직접 설치한 Docker에서 사용 (dockerd 옵션)
dockerd --userns-remap=default
```

> ⚠️ `dockerd` 명령 자체는 **Docker Desktop(Windows/macOS)에서는 직접 사용할 수 없다.** Docker Desktop은 이미 루트 권한으로 데몬을 관리하는 방식이라, 이 옵션은 **리눅스에 Docker를 직접 설치한 환경**에서만 의미가 있다.

---

## 4. 네트워크 격리 활용

Docker는 기본적으로 `docker0`(bridge)라는 네트워크를 제공하지만, 사용자가 직접 새 네트워크를 만들어 **격리 수준을 스스로 설계**할 수도 있다.

- 별도 네트워크를 만든다 = 그 네트워크 안에 있는 컨테이너들만 서로 통신 가능, 다른 네트워크와는 기본적으로 단절
- 네트워크 세분화, 컨테이너 간 트래픽 제한, 방화벽 규칙 분리 등에 활용
- 브릿지, 호스트, 오버레이 등 어떤 드라이버든 이 원리는 동일

```bash
docker network create --driver bridge isolated_network
docker network inspect isolated_network   # 서브넷/게이트웨이 확인
```

## 5. 실습: 두 개의 MariaDB를 격리했다가 다시 연결하기

### 5.1 새 네트워크 생성 및 확인

```bash
docker network create --driver bridge isolated_network
docker network inspect isolated_network
# Subnet: 192.168.0.0/19, Gateway: 192.168.0.1 (환경에 따라 다를 수 있음)
```

### 5.2 서로 다른 네트워크에 컨테이너 2개 기동

```bash
# MariaDB-1 : 기본 bridge 네트워크 사용 (네트워크 미지정)
docker run --rm -e MARIADB_ROOT_PASSWORD= -p 13306:3306 --name MariaDB-1 mariadb

# MariaDB-2 : 새로 만든 isolated_network 지정
docker run --rm -e MARIADB_ROOT_PASSWORD= -p 23306:3306 \
  --network isolated_network --name MariaDB-2 mariadb
```

### 5.3 네트워크가 다름을 확인

```bash
docker inspect MariaDB-1   # IPAddress 예: 172.17.0.2 (기본 bridge 대역)
docker inspect MariaDB-2   # IPAddress 예: 192.168.0.2 (isolated_network 대역)
```

각 컨테이너에 접속해 서로 다른 DB를 만들어봐도(`CREATE DATABASE db1;` / `CREATE DATABASE db2;`) 완전히 독립적으로 동작.

### 5.4 격리 상태에서는 서로 접근 불가 (ping 실패)

```bash
# 각 컨테이너 내부에서 ping 도구 설치 후 테스트
apt-get update && apt-get install -y iputils-ping

ping <상대방 IP>   # 응답 없음 (Hold 상태) — 서로 다른 네트워크라 통신 불가
```

### 5.5 `docker network connect`로 연결

```bash
docker network connect isolated_network MariaDB-1
```

연결 후:

```bash
docker network inspect isolated_network   # MariaDB-1, MariaDB-2 둘 다 포함된 것 확인

docker inspect MariaDB-1   # IP가 2개로 늘어남 (기존 bridge IP + isolated_network IP)

# 이제 ping도 정상 응답
ping <MariaDB-2의 isolated_network IP>

# DB도 상호 접속 가능
mariadb -h <MariaDB-2 IP> -u root -p   # 비밀번호 미설정이면 그냥 Enter
show databases;   # db2가 보이면 정상 연결 확인
```

> 연결을 다시 끊고 싶다면: `docker network disconnect isolated_network MariaDB-1`

## 6. 명령어 레퍼런스

| 명령어 | 설명 |
|---|---|
| `docker network create --driver <드라이버> <이름>` | 새 네트워크 생성 (bridge/host/overlay 등) |
| `docker network inspect <이름>` | 서브넷/게이트웨이/소속 컨테이너 확인 |
| `docker network connect <네트워크> <컨테이너>` | 실행 중인 컨테이너를 다른 네트워크에도 추가 가입 |
| `docker network disconnect <네트워크> <컨테이너>` | 특정 네트워크에서 컨테이너 제외 |
| `docker run --cpus="<코어수>" --memory="<용량>"` | cgroups 기반 리소스 제한 |
| `docker inspect <컨테이너>` | 할당된 IP, 네트워크 정보 등 상세 확인 |

## 7. 핵심 정리 (체크리스트)

- [ ] 컨테이너는 네임스페이스 단위(프로세스/네트워크/파일시스템)로 서로 격리됨
- [ ] `--cpus`, `--memory`로 리소스(cgroups)를 제한해 무한정 자원 점유를 방지
- [ ] 루트 사용자 대신 권한이 낮은 사용자로 매핑(`--userns-remap`)해서 공격 표면을 줄임 (단, 이는 리눅스 직접 설치 Docker 전용, Docker Desktop에서는 불가)
- [ ] 새 네트워크를 만들면 완전히 격리된 통신 공간이 생김 — 다른 네트워크와는 기본적으로 통신 불가
- [ ] 서로 다른 네트워크의 컨테이너를 통신시키려면 `docker network connect`로 같은 네트워크에 함께 소속시켜야 함
- [ ] `docker inspect`로 실제 할당된 IP와 네트워크를 항상 직접 확인하는 습관
