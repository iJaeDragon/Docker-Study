# Docker Secrets Management 레퍼런스

## 1. Secrets란

- **Secret** = 보안이 필요한 민감한 데이터(비밀번호, API 키 등)를 안전하게 저장·전달하기 위한 기능.
- **⚠️ 중요한 전제조건: Docker Secrets는 일반 Docker에서는 사용할 수 없고, 오직 Docker Swarm 모드에서만 사용 가능하다.** (Swarm 클러스터를 `docker swarm init`으로 구성한 상태여야 함)
- Key-Value 구조 — 이름(Key)과 그 안에 담긴 데이터(Value)로 구성.

> 참고: HashiCorp Vault 같은 외부 전용 시크릿 관리 서비스를 쓰는 경우도 많지만, 이 문서에서는 **Docker에 기본 내장된 Secrets 기능**을 다룬다.

---

## 2. Secrets 명령어 레퍼런스

| 명령어 | 설명 |
|---|---|
| `docker secret create <이름> <파일 또는 ->` | 새 시크릿 생성 (표준입력으로도 생성 가능) |
| `docker secret ls` | 생성된 시크릿 목록 확인 (값은 안 보임, 이름/생성일만) |
| `docker secret inspect <이름>` | 상세 정보 확인 (역시 실제 값은 노출되지 않음) |
| `docker secret rm <이름>` | 시크릿 삭제 |
| `docker service create --secret <시크릿명> <이미지>` | 서비스 생성 시 시크릿을 컨테이너에 전달 |

### 시크릿 생성 예시

```bash
# 방법 1: echo + 파이프로 표준입력을 통해 생성
echo "mysecretdata" | docker secret create my_secret -

# 방법 2: 임의 비밀번호를 시크릿으로 생성
echo "qwer1234" | docker secret create mydb_password -
```

> 명령어 끝의 `-`(하이픈)을 반드시 붙여야 표준입력(stdin)으로부터 값을 읽어들인다.

```bash
docker secret ls
# NAME             CREATED
# my_secret        ...
# mydb_password    ...
```

## 3. ⚠️ 기억해야 할 핵심 — "저장은 암호화, 사용은 평문"

<img width="1082" height="473" alt="image" src="https://github.com/user-attachments/assets/943702d7-bc27-4daa-840a-45f52f8946bd" />

- Swarm Manager에 **저장되어 있는 상태**에서는 시크릿 값이 **암호화**되어 있다. `docker secret ls`나 `docker secret inspect`로도 실제 값(원문)은 절대 보이지 않는다.
- **하지만** 그 시크릿을 사용하는 서비스/컨테이너 **내부**에서는, 파일 형태로 마운트되면서 **평문(plain text)으로 그대로 보인다.**
- 즉 "저장소에서는 안전하지만, 실행 중인 컨테이너 안에 접근할 수 있는 사람에게는 그대로 노출된다"는 뜻 — **아주 민감한 데이터(진짜 운영 비밀번호 등)를 다룰 때는 이 특성을 반드시 인지하고 주의해서 사용**해야 한다.

컨테이너 내부에서 시크릿은 기본적으로 `/run/secrets/<시크릿명>` 경로에 파일로 마운트된다.

## 4. 실습 1 — Redis 서비스에 Secret 전달하기

```bash
# 1) 시크릿 생성 (이미 위에서 만든 my_secret 재사용 가능)
echo "mysecretdata" | docker secret create my_secret -

# 2) 시크릿을 포함해서 Redis 서비스 생성
docker service create --name MyRedis --secret my_secret redis:alpine

# 3) 생성된 컨테이너에 접속 (bash가 없으면 sh 사용)
docker ps                     # Redis 컨테이너 ID 확인
docker exec -it <컨테이너ID> sh

# 4) 시크릿이 파일로 전달됐는지 확인
ls -l /run/secrets/
cat /run/secrets/my_secret    # → mysecretdata (평문으로 보임)
```

### Redis Key-Value로 시크릿 값 활용

```bash
# 파일 내용을 그대로 Redis에 저장
redis-cli set my-secret-key "$(cat /run/secrets/my_secret)"

# 확인
redis-cli
> get my-secret-key
"mysecretdata"
```

## 5. 실습 2 — MariaDB 서비스에서 루트 비밀번호를 Secret으로 지정하기

### 5.1 비밀번호용 시크릿 생성

```bash
echo "qwer1234" | docker secret create mydb_password -
```

### 5.2 MariaDB 서비스 생성 (source ↔ target 매핑 구조)

```bash
docker service create \
  --name mydb \
  --replicas 1 \
  --secret source=mydb_password,target=mariadb_root_password \
  --env MARIADB_ROOT_PASSWORD_FILE=/run/secrets/mariadb_root_password \
  mariadb:latest
```

- `source=mydb_password`: **어떤 시크릿을 가져올지** (2.1에서 만든 시크릿명)
- `target=mariadb_root_password`: 컨테이너 내부에서 **어떤 파일명으로 저장할지** (`/run/secrets/mariadb_root_password`로 마운트됨)
- `MARIADB_ROOT_PASSWORD_FILE` 환경변수로 MariaDB 이미지에게 "루트 비밀번호를 이 파일에서 읽어라"고 알려줌

### 5.3 접속 테스트

```bash
docker ps                          # mydb 컨테이너 확인
docker exec -it <컨테이너ID> bash

mariadb -h 127.0.0.1 -u root -p
# Enter password: qwer1234 (직접 만든 비밀번호 입력, 화면엔 안 보임)
```

정상적으로 비밀번호(`qwer1234`)를 입력하면 접속 성공 — 시크릿에 저장했던 값이 실제 DB 루트 비밀번호로 적용된 것을 확인.

## 6. 핵심 정리 (체크리스트)

- [ ] Docker Secrets는 **Swarm 모드에서만** 사용 가능 (`docker swarm init` 되어 있어야 함)
- [ ] `docker secret create <이름> -` (echo와 파이프로 표준입력 이용)로 생성
- [ ] `docker secret ls`/`inspect`로는 **원문이 노출되지 않음** (저장소 레벨 암호화)
- [ ] 그러나 **서비스에 연결된 컨테이너 내부**(`/run/secrets/<이름>`)에서는 **평문으로 노출**된다는 점 반드시 인지
- [ ] `--secret <이름>`으로 간단히 전달하거나, `--secret source=<시크릿>,target=<파일명>`으로 컨테이너 내 파일명을 다르게 지정 가능
- [ ] 실제 운영에서는 비밀번호를 직접 Secrets에 넣기보다, 민감도가 낮은 설정값 위주로 사용하고 진짜 중요한 정보는 별도의 전용 시크릿 관리 도구(Vault 등) 사용을 고려
