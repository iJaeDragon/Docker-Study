# DB 컨테이너 외부 접속 (포트 매핑)

## 배경
- 지금까지는 `docker exec`로 **컨테이너 내부에 들어가서** DB 클라이언트로 접속
- 실제로는 호스트 PC(또는 다른 서비스)에서 **컨테이너 외부에서 직접 접속**하는 경우가 더 많음
- 이를 위해 DB 컨테이너에도 **포트 매핑**이 필요

## 실행 예시
```
docker run --name myMariaDB -e MARIADB_ALLOW_EMPTY_ROOT_PASSWORD=true -d -p 13306:3306 mariadb
```
- `3306`: MariaDB/MySQL의 **컨테이너 내부 기본 포트**
- `13306`: 호스트 PC에서 접속할 때 사용할 포트
  - 호스트에서 기본 포트(3306)가 이미 다른 프로그램에 의해 사용 중이면, 이렇게 **다른 번호로 변경해서 매핑** 가능
- 즉 호스트 PC의 `13306`으로 접속하면 컨테이너 내부 `3306`이 응답

## 외부 클라이언트로 접속 테스트
- **MySQL Workbench** (Win/Mac/Linux 무료) 또는 **HeidiSQL** (Windows 전용, 무료)로 접속 가능
- 접속 정보
  - Host: 호스트 PC의 IP (또는 `localhost`)
  - Port: **매핑해둔 호스트 포트** (예: `13306`)
  - User: `root`
  - Password: 비워둠 (루트 패스워드 미설정 옵션으로 기동했으므로)
- 접속 성공 시 호스트 PC의 클라이언트 툴에서 **컨테이너 내부 DB에 직접 접근** 가능

## 핵심 포인트
> DB 컨테이너도 웹서버와 동일하게 `-p [호스트포트]:[컨테이너포트]`로 매핑하면, 외부 GUI 클라이언트(Workbench, HeidiSQL 등)에서 컨테이너 내부 데이터베이스에 바로 접속할 수 있다. 호스트에서 기본 포트가 이미 사용 중이라면 호스트 쪽 포트 번호만 자유롭게 바꿔서 매핑하면 된다.
