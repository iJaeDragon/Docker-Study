# Docker 컨테이너 (요약)

## 컨테이너 vs 이미지
- **이미지(Image)**: 컨테이너 실행을 위한 템플릿, 상태(state)를 가지지 않는 읽기 전용
- **컨테이너(Container)**: 이미지를 실행(실체화)한 상태, 격리된 자원/네트워크를 쓰는 독립 실행 단위
- 컨테이너 내부에서만 파일 변경, 로그 생성 등 실제 작업이 가능
- 동일 이미지로 여러 컨테이너를 독립적으로 여러 개 기동 가능 (예: MySQL 이미지 → 컨테이너 3개 = 독립된 DB 3개)
- 컨테이너 기동 시 고유한 **컨테이너 ID**(64비트)가 자동 부여되며, 별도로 **컨테이너 이름**도 지정 가능

| 명령어 | 동작 |
|---|---|
| `docker create` | 컨테이너 생성 (Created 상태, 아직 실행 전) |
| `docker start` | Created/Stopped → Running |
| `docker run` | create + start를 한 번에 실행 |
| `docker pause` / `unpause` | Running ↔ Paused |
| `docker stop` | Running → Stopped |
| `docker rm` | 컨테이너 삭제 (Created 또는 Stopped 상태에서만 가능, Running 상태에서는 오류) |

> ⚠️ 삭제(Deleted)된 컨테이너는 이전 상태로 복구 불가능. 컨테이너 내부에만 저장된 데이터는 삭제 시 함께 소멸되므로, 유지해야 할 데이터는 **외부 저장소와 연결(볼륨 마운트)**해서 관리해야 함

## `docker run` 주요 옵션

```
docker run [옵션] 이미지이름:태그
```

- **태그(tag)**: 이미지 뒤에 `:` 로 버전이나 상태를 표시 (예: `1.0`, `dev`, `fix` 등 자유롭게 지정 가능)

| 옵션 | 의미 |
|---|---|
| `-d`, `--detach` | 백그라운드(데몬) 모드로 실행 |
| `-p`, `--publish` | 호스트 ↔ 컨테이너 포트 연결 |
| `-v` | 볼륨 마운트 (호스트 디렉토리와 연결해 데이터 보존) |
| `-e` | 환경 변수 지정 |
| `--name` | 컨테이너 이름 지정 (미지정 시 랜덤 이름 부여) |
| `--rm` | 컨테이너 정지 시 자동 삭제 |
| `-it` | Interactive + TTY, 키보드 입력을 컨테이너로 전달 |
| `--link` | 컨테이너 간 연결 |

## 한 줄 정리
> 이미지를 실행하면 컨테이너가 되고, 컨테이너는 Created → Running → (Paused/Stopped) → Deleted 순으로 상태가 변한다. 삭제는 되돌릴 수 없으므로 데이터는 항상 외부에 보존해야 한다.
