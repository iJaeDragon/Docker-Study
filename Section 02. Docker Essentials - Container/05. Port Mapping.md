# Docker 포트 매핑 (Port Mapping)

## 개념
- 컨테이너는 호스트 PC와 **독립된 네트워크 공간**에서 동작
- 컨테이너 내부 서비스(DB, 웹서버 등)를 호스트 PC 외부에서 접속하려면 **포트 매핑**이 필요
- 매핑 정보가 없으면 호스트에서 해당 포트로 접속해도 컨테이너에 도달하지 못함

## 옵션 사용법
```
docker run -p [호스트 포트]:[컨테이너 포트] [이미지명]:[태그]
```
- `-p` 또는 `--publish` 옵션 사용
- `:` 기준 **왼쪽 = 호스트 포트**, **오른쪽 = 컨테이너 포트**

### 예시
```
docker run -p 80:8080 tomcat
```
→ 호스트 PC의 80번 포트로 접속하면, 컨테이너 내부 8080번 포트(Tomcat 기본 포트)로 연결됨

```
docker run -p 80:80 nginx
```
→ nginx는 기본적으로 컨테이너 내부에서 80번 포트로 서비스되므로, 호스트 80 ↔ 컨테이너 80으로 매핑

## 실습 포인트 (nginx)
- **포트 매핑 없이 실행** → 호스트 브라우저(`localhost`, `127.0.0.1` 등)에서 접속 불가
  - 단, 컨테이너 **내부**에서는 `docker exec -it [name] bash` 후 `curl http://127.0.0.1`로 정상 응답 확인 가능 → 컨테이너 자체는 잘 작동 중이나 외부 연결만 안 되는 상태
- **`-p 80:80`으로 재실행** → 호스트 브라우저에서도 정상 접속됨

## 함께 자주 쓰는 옵션 조합
| 옵션 | 설명 |
|---|---|
| `-d` | 백그라운드(detach) 모드, 로그 안 보이고 컨테이너 ID만 출력 |
| `--rm` | 컨테이너 정지 시 자동 삭제 (정지해도 목록에 안 남음) |
| `docker system prune` | 정지된 컨테이너, 미사용 네트워크/이미지 일괄 정리 |
| `docker exec -it [id/name] bash` | 실행 중인 컨테이너 내부 접속 |

> 컨테이너 ID는 **앞부분 일부만 입력**해도 다른 컨테이너와 겹치지 않으면 동일하게 명령 수행 가능 (예: `docker stop 408`)

## `--rm` (정지 시 자동 삭제)
​```
docker run --rm -p 80:80 nginx
​```
- 컨테이너가 **정지(stop)되는 순간 자동으로 삭제(rm)**까지 처리해주는 옵션
- `--rm` 없이 `stop`만 하면 컨테이너는 **Exited 상태로 목록에 남아있음** → 이후 `rm`으로 별도 삭제 필요
- `--rm`을 붙이면 정지와 동시에 목록에서 완전히 사라짐 (`docker ps -a`로 확인해도 안 보임)
- 대시(`-`)가 **2개**라는 점 주의 (`-p`, `-d`는 1개, `--rm`, `--name`은 2개)

> 일회성 테스트용 컨테이너를 기동할 때 유용 (정지 후 정리할 필요 없이 자동으로 깔끔하게 삭제됨)

## 한 줄 정리
> `-p 호스트포트:컨테이너포트` 로 호스트와 컨테이너 사이 포트를 연결해야만 외부(웹브라우저 등)에서 컨테이너 서비스에 접근할 수 있다.
