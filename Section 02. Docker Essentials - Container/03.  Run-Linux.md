# Docker 컨테이너 실습

## 실습 1: `docker run ubuntu:16.04`
- `docker run ubuntu:16.04` 실행 → 로컬에 이미지 없으면 **Docker Hub**에서 자동 `pull` 후 `create` + `start` 진행
- 이미지는 여러 개의 **레이어**로 구성되어 다운로드됨
- 실행 후 `docker container ls` (= `docker ps`)로 확인하면 **아무것도 안 뜸**
  → 컨테이너는 **내부 프로세스가 종료되면 컨테이너 자체도 종료**되기 때문 (Ubuntu 컨테이너는 실행할 프로세스가 없어서 즉시 종료)
- `docker ps -a` 로 확인하면 **Exited** 상태로 종료된 컨테이너 이력 확인 가능

## 실습 2: `-it` 옵션으로 컨테이너 유지하기
```
docker run -it ubuntu:16.04
```
- `-it` (Interactive + TTY): bash 쉘 프로세스를 계속 유지시켜, 키보드 입력을 컨테이너에 전달
- 실행하면 프롬프트가 **컨테이너 ID = 호스트네임**으로 바뀜 (`hostname` 명령으로 확인 가능)
- 새 터미널에서 `docker ps`로 확인하면 **Up** 상태(작동 중)로 표시됨
- 컨테이너 내부에서 `ls -al` 등 일반 리눅스 명령어 사용 가능
- `exit` 입력 시 bash 프로세스 종료 → 컨테이너도 함께 **Exited** 상태로 전환

## 이미지 확인 관련 명령어
| 명령어 | 설명 |
|---|---|
| `docker images` (또는 `docker image ls`) | 다운로드된 이미지 목록 확인 |
| `docker images \| grep ubuntu` (Windows: `findstr`) | 이미지 이름으로 필터링 |
| `docker version` | 클라이언트/서버 버전 확인 (둘 다 표시되면 정상 작동) |

## Docker Hub
- `hub.docker.com`에서 공개 이미지 검색 가능
- 이미지 페이지의 **Tags** 메뉴에서 사용 가능한 태그(버전) 확인 가능 (예: `16.04`, `rolling`, `noble` 등)
- 태그별 상세 페이지에서 `docker pull ubuntu:16.04` 같은 다운로드 명령어 제공
- 회원가입 시 개인 계정으로 이미지 관리 가능

## 핵심 포인트
> 컨테이너는 **하나의 프로세스**와 같아서, 그 프로세스가 끝나면 컨테이너도 종료된다. 프로세스를 계속 유지하려면 `-it` 옵션으로 쉘(bash) 같은 지속적인 프로세스를 실행시켜야 한다.
