# Docker 볼륨 마운트 (Node.js)

## 실행 명령어
```
docker run -it -v .:/app -p 8000:8000 node:alpine
```
- `node:alpine`: Node 이미지 중 경량 버전 (약 40MB)
- `-p 8000:8000`: 호스트 8000 ↔ 컨테이너 8000 포트 매핑
- `-v .:/app`: **볼륨 마운트** — 호스트의 현재 디렉토리(`.`)를 컨테이너의 `/app` 디렉토리와 연결
- `-it`: 실행과 동시에 컨테이너 내부 쉘로 진입

## 볼륨(`-v`) 옵션이란?
- 호스트 PC의 특정 디렉토리와 컨테이너 내부 디렉토리를 **연결(마운트)**하는 기능
- 문법: `-v [호스트 경로]:[컨테이너 경로]`
- 포트 매핑이 네트워크를 연결하는 것이라면, 볼륨 마운트는 **파일 시스템(디렉토리)을 연결**하는 것
- 호스트 ↔ 컨테이너 **양방향으로 파일 변경 사항이 실시간 반영**됨
  - 호스트에서 파일 생성/수정 → 컨테이너에도 즉시 반영
  - 컨테이너 내부에서 파일 생성/수정 → 호스트에도 즉시 반영 (삭제도 동일)

## 실습 흐름
1. 호스트 PC의 `mynodejs` 폴더(`app.js`, `package.json` 포함)에서 위 명령어 실행
2. 컨테이너 내부 `/app`으로 이동 → 호스트와 동일한 파일 확인됨
3. `node app.js` 실행 시 `express` 모듈 없음 오류 발생
4. 컨테이너 내부에서 `npm install express` 실행
   - 생성된 `node_modules`, `lock` 파일이 **호스트 PC에도 그대로 반영됨** (볼륨 마운트 덕분)
5. 다시 `node app.js` 실행 → 8000 포트로 정상 기동
6. 호스트 브라우저에서 `localhost:8000` 접속 → 컨테이너 내부 Node 웹서버 응답 확인

## 핵심 포인트
> `-v 호스트경로:컨테이너경로` 로 파일 시스템을 마운트하면, 컨테이너 안에서 작업한 내용이 호스트에도 그대로 남는다(반대도 동일). 포트 매핑(`-p`)과 볼륨 마운트(`-v`)를 함께 쓰면, 호스트의 소스 코드를 컨테이너에서 그대로 실행하고 브라우저로 결과까지 확인하는 개발 환경을 구성할 수 있다.
