# Docker 명령어 최종 정리

## 명령어 구조
```
docker [리소스] [명령어] [옵션] [대상]
```
- 리소스: `container`, `image`, `network`, `volume` 등
- 특정 리소스에서만 유일하게 쓰이는 명령어는 **리소스명 생략 가능**
  - 예: `docker run` = `docker container run`
  - `docker rm` → 리소스 생략 시 기본적으로 **컨테이너** 삭제로 인식
  - 이미지 삭제는 반드시 `docker image rm`으로 명시

---

## 1. 컨테이너 생명주기(Lifecycle) 명령어

| 명령어 | 옵션 | 설명 / 사용 시점 |
|---|---|---|
| `docker create [이미지]` | - | 컨테이너 생성만 함 (Created 상태, 아직 실행 안 됨) |
| `docker start [id/name]` | - | Created/Stopped 상태 → Running으로 전환 |
| `docker run [이미지]` | - | `create` + `start`를 한번에 실행. 가장 많이 쓰는 명령어 |
| `docker pause [id/name]` | - | 실행 중인 컨테이너 일시 정지 (프로세스는 메모리에 유지) |
| `docker unpause [id/name]` | - | Paused → Running 복귀 |
| `docker stop [id/name]` | - | Running → Stopped. DB 등 데몬성 프로세스는 `Ctrl+C`로 안 꺼질 수 있어 이 명령 사용 |
| `docker rm [id/name]` | - | 컨테이너 삭제. **Created/Stopped 상태에서만 가능**, Running 상태에서는 오류 발생 |

> 삭제(Deleted)된 컨테이너는 복구 불가. 컨테이너 내부 데이터만 저장돼 있으면 삭제 시 함께 소멸되므로, 유지할 데이터는 볼륨 마운트로 외부에 보존해야 함.

---

## 2. 조회 / 확인 명령어

| 명령어 | 옵션 | 설명 / 사용 시점 |
|---|---|---|
| `docker container ls` (= `docker ps`) | - | 현재 **실행 중인** 컨테이너 목록 확인 |
| `docker ps` | `-a` | 실행 중 + 정지된(Exited) 컨테이너까지 **전체** 확인 |
| `docker logs [id/name]` | - | 컨테이너의 로그(콘솔 출력) 확인 |
| `docker exec [id/name] [명령어]` | `-it` | 실행 중인 컨테이너 내부에 새 프로세스(예: bash) 실행해서 접속. DB 클라이언트 접속, 파일 확인 등에 사용 |
| `docker container inspect [id/name]` | - | 컨테이너의 상세 설정/환경 정보 조사 |
| `docker version` | - | 클라이언트/서버 버전 확인 (둘 다 나오면 정상 작동) |
| `docker images \| grep [키워드]` (Windows: `findstr`) | - | 이미지 목록을 이름으로 필터링해서 확인 |

## 3. 이미지 관리 명령어

| 명령어 | 옵션 | 설명 / 사용 시점 |
|---|---|---|
| `docker image ls` (= `docker images`) | - | 로컬에 다운로드된 이미지 목록 확인 |
| `docker image rm [이미지]` | - | 이미지 삭제. 해당 이미지로 **실행 중인 컨테이너가 있으면 삭제 불가** → 컨테이너 종료 후 삭제해야 함 |
| `docker pull [이미지]:[태그]` | - | 이미지 다운로드 (Docker Hub 등 레지스트리에서). `run` 안에 이 과정이 포함되어 있음 |
| `docker push [이미지]:[태그]` | - | 이미지를 레지스트리에 업로드 |

> 태그를 명시하지 않으면 자동으로 `latest` 태그가 적용됨 (예: `docker run mariadb` = `docker run mariadb:latest`)

## 4. 네트워크 / 정리 명령어

| 명령어 | 옵션 | 설명 / 사용 시점 |
|---|---|---|
| `docker network ls` | - | 네트워크 목록 확인 |
| `docker network inspect` | - | 네트워크 상세 정보 조사 |
| `docker system prune` | - | 정지된 컨테이너, 태그 없는(불명확한) 이미지, 미사용 네트워크를 **한번에 일괄 정리** |

## 5. `docker run`에서 자주 쓰는 옵션 총정리

```
docker run [옵션들] 이미지이름:태그
```

| 옵션 | 축약 여부 | 설명 / 사용 시점 |
|---|---|---|
| `-d`, `--detach` | - | 백그라운드(데몬) 모드 실행. 로그 안 보이고 컨테이너 ID만 출력. 서버/DB처럼 계속 띄워둘 서비스에 사용 |
| `-p`, `--publish` | `-p [호스트포트]:[컨테이너포트]` | 호스트 ↔ 컨테이너 **포트 연결**. 웹서버/DB 등 외부에서 접속해야 하는 서비스에 필수 |
| `-v` | `-v [호스트경로]:[컨테이너경로]` | **볼륨 마운트**. 호스트 디렉토리와 컨테이너 디렉토리를 연결해 양방향으로 파일 동기화. 데이터 보존, 소스코드 실시간 반영에 사용 |
| `-e` | `-e [환경변수]=[값]` | 환경 변수 지정. DB 루트 패스워드 설정 등에 사용 (예: `-e MARIADB_ALLOW_EMPTY_ROOT_PASSWORD=true`) |
| `--name` | - | 컨테이너 이름 직접 지정. 미지정 시 랜덤 이름 부여 → 관리 편의를 위해 지정 권장 |
| `--rm` | 대시 2개 | 컨테이너 **정지 시 자동 삭제**. 일회성 테스트 컨테이너에 유용 (정지 후 `docker ps -a`에도 안 남음) |
| `-it` (`-i` + `-t`) | - | Interactive + TTY. 키보드 입력을 컨테이너로 전달하며 쉘(bash 등) 프로세스를 유지시킴. 컨테이너 내부에 직접 들어가서 작업할 때 사용 |
| `--link` | - | 컨테이너 간 연결 (레거시 방식, 컨테이너끼리 통신 설정) |

## 6. 실전 조합 예시

| 목적 | 명령어 예시 |
|---|---|
| Ubuntu 컨테이너를 계속 유지하며 접속 | `docker run -it ubuntu:16.04` |
| MariaDB 백그라운드 실행 + 이름 지정 | `docker run -d --name my-mariadb -e MARIADB_ALLOW_EMPTY_ROOT_PASSWORD=true mariadb` |
| DB를 외부 클라이언트(Workbench 등)에서 접속 가능하게 | `docker run -d --name myMariaDB -e MARIADB_ALLOW_EMPTY_ROOT_PASSWORD=true -p 13306:3306 mariadb` |
| nginx 웹서버를 외부에서 접속 가능하게 | `docker run -d -p 80:80 --rm nginx` |
| 실행 중인 컨테이너 내부 접속 | `docker exec -it [컨테이너명] bash` |
| 소스코드를 컨테이너와 실시간 공유하며 개발 | `docker run -it -v .:/app -p 8000:8000 node:alpine` |
| 정지된 컨테이너/미사용 리소스 일괄 정리 | `docker system prune` |

## 한 줄 정리
> 컨테이너는 `create → start`(= `run`) → `stop`/`pause` → `rm` 순으로 상태가 바뀌며, `-d`(백그라운드) · `-p`(포트) · `-v`(볼륨) · `-e`(환경변수) · `--name`(이름) · `-it`(대화형 접속) 옵션을 조합해서 실행하는 것이 Docker 컨테이너 운용의 기본이다.
