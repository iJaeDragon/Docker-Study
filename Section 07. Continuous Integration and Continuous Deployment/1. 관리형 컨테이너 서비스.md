# 클라우드 서비스 모델 (IaaS / PaaS / SaaS)과 Docker의 위치

---

## 1. IaaS / PaaS / SaaS 한눈에 정리

| 구분 | 제공하는 것 | 한 줄 비유 | 예시 |
|---|---|---|---|
| **IaaS** (Infrastructure as a Service) | 서버, 스토리지, 네트워크, VM, 컨테이너 등 **가장 기본적인 인프라** | "서버 컴퓨터 한 대를 빌린다" | 가상 서버(VM), 스토리지, 네트워크, 컨테이너 인프라 |
| **PaaS** (Platform as a Service) | 이미 구축된 **플랫폼 위에서 개발·배포·자동화** | "밭(인프라)은 이미 있으니 농사(개발)만 지으면 된다" | **Docker**, Kubernetes, GitHub, GitLab, CI/CD 자동화, 오토스케일링, 클러스터링 |
| **SaaS** (Software as a Service) | 이미 완성되어 **바로 사용 가능한 소프트웨어** | "완제품을 그냥 쓴다" | Gmail, 네이버 메일, 클라우드 디스크(사진 백업 등), 마켓플레이스, 빌링 시스템, 홈쇼핑몰 |

---

## 2. Docker는 어디에 속하는가

<img width="857" height="521" alt="image" src="https://github.com/user-attachments/assets/6e31a21b-2952-44b6-ac23-93b84ec56987" />

**Docker는 PaaS(중간 계층)에 속한다.**

- IaaS처럼 인프라 자체(서버, 스토리지)를 제공하는 건 아니고
- SaaS처럼 완성된 최종 서비스를 제공하는 것도 아니며
- **개발한 결과물을 배포하고 운영할 수 있는 플랫폼**을 제공한다는 점에서 PaaS 성격에 해당

### PaaS 계층에서 Docker와 같이 언급되는 도구들

| 도구 | 역할 |
|---|---|
| **Docker** | 컨테이너 런타임 — 애플리케이션을 컨테이너로 패키징·실행 |
| **Kubernetes** | 컨테이너 런타임(Docker 등)을 효율적으로 다루는 "지휘자" — 오케스트레이션 |
| **GitHub / GitLab** | 소스 코드 관리 + 최근에는 CI/CD 기능도 통합 제공 (예: GitHub Actions) |

> 이 넷은 서로 배타적인 대체재가 아니라 **함께 쓰이는 조합**인 경우가 많다 (GitHub/GitLab에서 소스 관리 → Docker로 이미지 빌드 → Kubernetes로 배포/운영).

PaaS 영역에서 다뤄지는 다른 개념들: **오토 스케일링, 클러스터링, CI/CD 자동화, 컨테이너 오케스트레이션 도구** 전반.

---

## 3. 주요 클라우드 벤더

| 해외 | 국내 |
|---|---|
| AWS | 네이버 클라우드 |
| Microsoft Azure | NHN |
| Google Cloud Platform (GCP) | KT |

각 벤더는 자체적인 특징을 갖고 컴퓨팅, 스토리지, 네트워크, 컨테이너 관리 서비스 등을 제공한다.

---

## 4. 핵심 정리 (체크리스트)

- [ ] IaaS = 인프라(서버/스토리지/네트워크) 그 자체를 빌려 쓰는 것
- [ ] PaaS = 이미 구축된 플랫폼 위에서 개발/배포/자동화 — **Docker, Kubernetes, GitHub/GitLab이 여기 속함**
- [ ] SaaS = 완성된 소프트웨어를 그대로 사용 (Gmail 등)
- [ ] Docker는 PaaS 계층의 컨테이너 런타임이며, Kubernetes는 그 위에서 오케스트레이션을 담당하는 관계
- [ ] 클라우드 벤더(AWS/Azure/GCP/네이버클라우드 등)는 이 세 가지 서비스 모델을 모두 조합해서 제공
