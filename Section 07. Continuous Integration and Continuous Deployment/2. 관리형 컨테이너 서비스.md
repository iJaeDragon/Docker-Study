# AWS 관리형 컨테이너 서비스 (ECR / ECS) 레퍼런스

> 학습 회차: Docker(PaaS)가 클라우드에서 관리형 서비스로 어떻게 제공되는지, AWS Code 시리즈(CodeCommit/CodePipeline/CodeBuild) → ECR → ECS 파이프라인, ECR 인증/푸시/풀 실습
> 목적: 나중에 AWS에서 컨테이너 이미지를 저장·배포할 때 개념과 명령어를 바로 참고.

---

## 1. 배경 — Docker는 PaaS, AWS는 이를 관리형으로 제공

이전에 정리한 것처럼 Docker는 클라우드 서비스 분류상 **PaaS**에 해당한다. 지금까지는 이 PaaS 환경(Docker 설치, 이미지 생성, 컨테이너 관리)을 전부 **직접** 구축해왔다면(Docker Desktop 설치 등), AWS 같은 클라우드 벤더는 이 과정을 **관리형(Managed) 서비스**로 대신 제공해준다 — 설치·생성·재배포까지 자동화.

---

## 2. AWS 파이프라인 전체 흐름

<img width="779" height="308" alt="image" src="https://github.com/user-attachments/assets/ada5bfac-1f20-4f3a-a81e-605e55e93578" />

| AWS 서비스 | 역할 | 대응되는 일반 개념 |
|---|---|---|
| **CodeCommit** | 소스 코드 형상관리 | Git |
| **CodePipeline** | 전체 파이프라인 오케스트레이션(트리거, 단계 연결) | Jenkins의 파이프라인 기능 |
| **CodeBuild** | 소스를 가져와 빌드 → **컨테이너 이미지** 생성 | Jenkins의 build 단계 |
| **ECR** (Elastic Container Registry) | 빌드된 이미지 저장소 | Docker Hub / Harbor |
| **ECS** (Elastic Container Service) | 이미지를 가져와 실행하는 **관리형 컨테이너 오케스트레이션** | Docker Swarm / (경량) Kubernetes |

흐름: **소스 commit → CodeCommit → CodePipeline이 트리거 → CodeBuild가 빌드 후 이미지 생성 → ECR에 저장 → CodePipeline이 Deploy 단계 실행 → ECS가 ECR에서 이미지를 pull하여 새 태스크 기동**

---

## 3. ECS 배포 사이클 (Rolling 방식)

<img width="703" height="278" alt="image" src="https://github.com/user-attachments/assets/88bf62e1-d5b8-486c-b33c-8dc1c4efb7e7" />

1. **배포 전**: Old Task(v1)가 정상 서비스 중
2. **새 커밋 감지**: CodePipeline이 트리거되어 CodeBuild가 새 이미지를 빌드 → ECR에 push (이 시점까지 Old Task는 계속 서비스)
3. **New Task 실행**: ECS가 ECR에서 새 이미지를 pull하여 New Task(v2) 기동, Old Task는 여전히 서비스 중
4. **Old Task 종료**: New Task가 정상 확인되면 Old Task에 `Kill Task` — 이제 New Task만 서비스하는 상태로 전환

> **문제 발생 시(롤백)**: 별도의 특수한 롤백 명령이 있는 게 아니라, **동일한 사이클을 반대 방향으로** 실행한다 — 이전 버전 이미지로 New Task를 다시 띄우고, 문제가 있던 Task를 Kill.

## 4. ECS 핵심 개념

| 개념 | 설명 |
|---|---|
| **Cluster** | ECS 리소스를 묶는 단위. 먼저 클러스터를 구성해야 함 |
| **Task Definition** | 어떤 컨테이너에서 무슨 동작을 할지 정의하는 **정의 파일** (이미지, 포트, 리소스 등 명시) |
| **Task** | Task Definition을 실제로 실행한 인스턴스 |
| **Launch Type: EC2** | AWS가 제공하는 **가상 머신(EC2)** 위에 직접 클러스터/컨테이너 런타임을 구성해서 사용 |
| **Launch Type: Fargate** | **서버리스** — 서버(EC2 인스턴스)를 직접 관리하지 않고 컨테이너 런타임만 사용 |

> ECS는 Kubernetes의 관리형 버전인 **EKS**와는 별개다. EKS는 Kubernetes 자체의 관리형 서비스이고, **ECS는 AWS 자체의(Docker 기반) 오케스트레이션 서비스**다.

## 5. ECR vs Docker Hub

| 항목 | Docker Hub | Amazon ECR |
|---|---|---|
| Public 레포 | 무료 | 지원 |
| Private 레포 | 무료 플랜은 **1개만** 제공 | Public/Private 모두 폭넓게 지원 |
| 대안 | Harbor(자체 프라이빗 레지스트리 구축) | AWS 생태계와 통합되어 있어 ECS/EKS와 연동이 쉬움 |

## 6. ECR 사용 실습

### 6.1 사전 준비 — IAM 권한

AWS 콘솔의 **IAM**에서 사용자 생성 후, 최소 아래 권한을 가진 역할(Role)을 할당한다.

- `AmazonEC2ContainerRegistryFullAccess` (ECR 풀 액세스)

### 6.2 레파지토리 생성

AWS 콘솔 → **ECR** → Repositories → Create repository (Public 또는 Private 선택). 레파지토리 = 이미지를 저장할 이름이 부여된 공간.

### 6.3 로컬 PC에서 AWS CLI 설치 및 인증

```bash
# AWS CLI 설치 후 자격 증명 설정 (최초 1회)
aws configure

# ECR 로그인 → Docker 클라이언트에 인증 정보 전달
aws ecr get-login-password --region <리전> \
  | docker login --username AWS --password-stdin <AWS계정ID>.dkr.ecr.<리전>.amazonaws.com
```

> Docker Hub도 최초 사용 시 `docker login`으로 인증했던 것처럼, ECR도 별도의 인증 절차가 필요하다. 다만 ECR은 AWS CLI를 통해 발급받은 임시 토큰으로 로그인한다.

### 6.4 이미지 빌드 & 태그 & 푸시

```bash
# 1) 이미지 빌드
docker build -t my-app .

# 2) ECR 레파지토리 주소 형식으로 태그 재지정
#    형식: <AWS계정ID>.dkr.ecr.<리전>.amazonaws.com/<레파지토리명>:<태그>
docker tag my-app:latest <AWS계정ID>.dkr.ecr.<리전>.amazonaws.com/my-app:latest

# 3) ECR로 푸시
docker push <AWS계정ID>.dkr.ecr.<리전>.amazonaws.com/my-app:latest
```

> 태그에 호스트네임을 아무것도 안 붙이면 기본적으로 Docker Hub로 push되고, 위처럼 **ECR 주소를 호스트네임 자리에 명시**해야 ECR 레파지토리로 push된다.

### 6.5 이미지 풀 (다른 환경에서 받아 쓸 때)

```bash
docker pull <AWS계정ID>.dkr.ecr.<리전>.amazonaws.com/my-app:latest
```

## 7. 핵심 정리 (체크리스트)

- [ ] AWS Code 시리즈(CodeCommit/CodePipeline/CodeBuild) = Git + Jenkins 파이프라인 역할을 관리형으로 대체
- [ ] ECR = Docker Hub/Harbor 역할의 관리형 이미지 레지스트리
- [ ] ECS = Docker Swarm/Kubernetes 역할의 관리형 오케스트레이션 (EKS는 별개 — Kubernetes 전용 관리형 서비스)
- [ ] ECS Launch Type: **EC2**(직접 VM 관리) vs **Fargate**(서버리스)
- [ ] ECS 배포는 New Task 기동 → 정상 확인 → Old Task Kill 순서. 롤백도 동일한 사이클을 반대로 수행
- [ ] ECR 사용 전 IAM 권한 설정 필수, `aws ecr get-login-password` → `docker login` → `tag` → `push`/`pull` 순서로 사용
