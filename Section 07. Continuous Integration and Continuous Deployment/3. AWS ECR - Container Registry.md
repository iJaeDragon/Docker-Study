# AWS ECR 실습 — Access Key 발급부터 Push/Pull까지 (단계별 명령어)

---

## 0. 준비물

- AWS 계정 (콘솔 로그인 가능한 상태)
- 로컬 PC에 **AWS CLI** 설치 (버전 확인: `aws --version`)
- 로컬에 push해볼 Docker 이미지 하나 (이미 있는 것 아무거나 사용 가능)

> AWS 계정이 없다면 이 실습은 건너뛰어도 무방하다 — "이런 식으로 관리형 컨테이너 서비스를 쓸 수 있다"는 개념만 이해하고 넘어가도 이후 학습에 지장 없음.

---

## 1. Access Key 발급

1. AWS 콘솔 우측 상단 계정 메뉴 클릭 → **보안 자격 증명(Security credentials)**
2. **액세스 키(Access keys)** 섹션에서 기존 키를 사용하거나, 없으면 **새 액세스 키 생성**
3. **Access Key ID**와 **Secret Access Key** 두 값을 안전한 곳에 기록

> ⚠️ **Secret Access Key는 생성 시 딱 한 번만 화면에 표시된다.** 이후에는 다시 볼 수 없으므로, 분실했다면 새로 발급받아야 한다. Access Key ID는 언제든 콘솔에서 재확인 가능.

---

## 2. AWS CLI 설정

```bash
# 버전 확인 (설치 안 됐다면 OS별 공식 설치 가이드로 설치)
aws --version

# 자격 증명 등록
aws configure
```

`aws configure` 실행 시 순서대로 입력:

```
AWS Access Key ID [None]: <위에서 발급받은 Access Key ID>
AWS Secret Access Key [None]: <위에서 발급받은 Secret Access Key>
Default region name [None]: <예: us-east-1, ap-northeast-2 등 원하는 리전>
Default output format [None]: (그냥 Enter, 생략 가능)
```

> Region은 자유롭게 선택 가능. 기본값은 보통 `us-east-1`.

---

## 3. ECR Private Repository 생성

1. AWS 콘솔 검색창에 **ECR** 입력 → 이동
2. 왼쪽 메뉴에서 **Private registry → Repositories** 선택 (Public registry는 별도 영역)
3. **Create repository** 클릭
4. Visibility: **Private** 선택, Repository name 입력 (예: `cicd-web-project`)
   - 계정 ID가 자동으로 앞에 붙어 고유한 전체 경로가 만들어짐
5. 나머지 옵션은 기본값으로 두고 **Create repository**

생성된 레포지토리를 클릭하면 처음엔 이미지(태그)가 하나도 없는 빈 상태로 보인다. **레포지토리 = 저장 공간의 이름**이며, 그 안에 여러 태그의 이미지를 등록해서 쓰는 구조.

---

## 4. Push 명령 확인 & 실행 (AWS 콘솔이 자동 생성해주는 4단계)

레포지토리 화면에서 **"푸시 명령 보기(View push commands)"**를 클릭하면 OS별(macOS/Windows)로 아래 4단계 명령어를 그대로 보여준다.

### 4-1. ECR 로그인

```bash
aws ecr get-login-password --region <리전> \
  | docker login --username AWS --password-stdin <계정ID>.dkr.ecr.<리전>.amazonaws.com
```
→ `Login Succeeded` 메시지 확인.

### 4-2. (필요 시) 이미지 빌드

```bash
docker build -t cicd-web-project .
```
> **이미 갖고 있는 이미지를 재사용할 거라면 이 단계는 생략**하고 바로 4-3으로 이동.

### 4-3. ECR 형식으로 태그 변경

```bash
docker tag <기존 이미지명>:<기존 태그> \
  <계정ID>.dkr.ecr.<리전>.amazonaws.com/cicd-web-project:latest
```

- `<기존 이미지명>:<기존 태그>` 자리에는 **본인이 실제로 갖고 있는 이미지 이름**을 넣어야 한다 (AWS가 예시로 보여주는 이름과 다를 수 있으니 반드시 `docker images`로 실제 이름 확인 후 사용).

```bash
# 이미지 목록에서 본인 계정/이미지 이름 확인
docker images | grep <계정 또는 이미지 키워드>
# Windows: docker images | findstr <키워드>
```

### 4-4. ECR로 Push

```bash
docker push <계정ID>.dkr.ecr.<리전>.amazonaws.com/cicd-web-project:latest
```

- 최초 push는 전체 레이어를 올리느라 시간이 걸리지만, 이후 재push 시에는 **변경된 레이어만** 올라가서 빠르다.
- 완료 후 ECR 콘솔에서 레포지토리를 새로고침하면 `latest` 태그의 이미지가 등록된 것을 확인할 수 있다.

---

## 5. 삭제 후 Pull로 복원 테스트

```bash
# 로컬 이미지 삭제
docker rmi <계정ID>.dkr.ecr.<리전>.amazonaws.com/cicd-web-project:latest

# 삭제 확인 (검색되지 않아야 정상)
docker images | grep cicd-web-project

# ECR로부터 다시 pull
docker pull <계정ID>.dkr.ecr.<리전>.amazonaws.com/cicd-web-project:latest

# 복원 확인
docker images | grep cicd-web-project
```

정상적으로 다시 나타나면 ECR을 통한 push/pull 사이클이 완성된 것.

---

## 6. 전체 명령어 요약 (복붙용)

```bash
# 0) AWS CLI 준비
aws --version
aws configure

# 1) ECR 로그인
aws ecr get-login-password --region <리전> \
  | docker login --username AWS --password-stdin <계정ID>.dkr.ecr.<리전>.amazonaws.com

# 2) 태그 변경
docker tag <기존이미지>:<태그> <계정ID>.dkr.ecr.<리전>.amazonaws.com/<레포지토리명>:latest

# 3) Push
docker push <계정ID>.dkr.ecr.<리전>.amazonaws.com/<레포지토리명>:latest

# 4) (테스트) 삭제 후 Pull로 복원 확인
docker rmi <계정ID>.dkr.ecr.<리전>.amazonaws.com/<레포지토리명>:latest
docker pull <계정ID>.dkr.ecr.<리전>.amazonaws.com/<레포지토리명>:latest
```

---

## 7. 핵심 정리 (체크리스트)

- [ ] Access Key는 발급 즉시 Secret Key를 따로 저장해둘 것 (재확인 불가)
- [ ] `aws configure`로 Access Key/Secret Key/Region 등록 필수
- [ ] ECR도 Docker Hub처럼 **로그인(인증)이 먼저 필요** — `aws ecr get-login-password | docker login`
- [ ] `docker tag`로 이미지를 **ECR 주소 형식**(`계정ID.dkr.ecr.리전.amazonaws.com/레포지토리:태그`)으로 변환해야 push 가능
- [ ] 태그 변경 시 **실제 보유 중인 이미지 이름**을 정확히 사용할 것 (AWS 예시 이름을 그대로 복붙하지 말 것)
- [ ] `docker push`/`docker pull` 명령 자체는 Docker Hub 쓸 때와 동일, 대상 주소만 ECR로 바뀜
