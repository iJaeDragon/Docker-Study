# Docker 레지스트리 (Registry) 요약

## 레지스트리 개념
- **Docker Registry**: 이미지가 저장되는 저장소 서비스
- **Repository**: 레지스트리 안에서 이미지 하나하나가 저장되는 개별 공간
- **Public Registry**: 누구나 접근 가능 (예: Docker Hub `hub.docker.com`)
- **Private Registry**: 인증된 사용자만 접근 가능. 기업 내부 이미지 관리, CI/CD 자동화 파이프라인에 사용

### 대표적인 레지스트리 서비스
| 서비스 | 특징 |
|---|---|
| **Docker Hub** (`docker.io`) | 가장 대중적인 퍼블릭 레지스트리. 무료 계정은 프라이빗 레포지토리 개수 제한 있음 |
| **Harbor** | 오픈소스 기반, 자체 프라이빗 레지스트리 구축 가능 |
| **Amazon ECR** | AWS의 컨테이너 레지스트리 서비스, 퍼블릭/프라이빗 모두 지원 |

> 이미지명에서 레지스트리 주소가 생략되면 기본값으로 **`docker.io`(Docker Hub)**가 사용됨

## 로컬 작업 흐름 정리

<img width="2000" height="1120" alt="image" src="https://github.com/user-attachments/assets/2d5c3e74-0cdd-4810-8f1a-e1fa40723940" />


```
Dockerfile 작성 → build → 이미지 생성(로컬) → run → 컨테이너 실행
                                     ↓
                          (컨테이너 상태 변경 후) commit → 새 이미지
                                     ↓
                                  tag → 이미지명/태그 변경
                                     ↓
                          save → tar 파일로 압축 → 다른 PC로 이동 → load → 이미지 등록
```

| 명령어 | 설명 |
|---|---|
| `docker commit [컨테이너] [이미지명:태그]` | 실행 중이던 컨테이너의 현재 상태를 새 이미지로 저장 |
| `docker tag [원본이미지] [새이미지명:태그]` | 이미지에 새로운 이름/태그 부여 (원본은 유지됨) |
| `docker save -o [파일명.tar] [이미지명:태그]` | 이미지를 압축 파일(tar)로 저장 → USB, 네트워크 등으로 이동 가능 |
| `docker load -i [파일명.tar]` | tar 파일을 다른 PC의 로컬 이미지 목록에 등록 |

## 레지스트리 업로드/다운로드

| 명령어 | 설명 |
|---|---|
| `docker push [이미지명:태그]` | 로컬 이미지를 지정된 레지스트리에 업로드 (`docker image push` 생략형) |
| `docker pull [이미지명:태그]` | 레지스트리에서 로컬로 이미지 다운로드 |

## 로컬(자체) 레지스트리 구축 실습

### 1. 로컬 레지스트리 컨테이너 실행
```
docker run -d -p 5000:5000 --name registry registry
```
- `-d`: 백그라운드 실행
- `-p 5000:5000`: 로컬 레지스트리가 사용하는 **5000번 포트**를 호스트와 매핑

### 2. 이미지 이름을 로컬 레지스트리 주소로 변경
```
docker tag ubuntu localhost:5000/ubuntu
```
- 이미지명 앞에 **레지스트리 주소(`localhost:5000`)**를 붙여야 해당 레지스트리로 인식됨
- 이름/태그를 명시하지 않으면 기본적으로 Docker Hub(`docker.io`)로 인식되기 때문에, 로컬 레지스트리를 쓰려면 반드시 주소를 명시적으로 붙여줘야 함

### 3. 로컬 레지스트리로 업로드
```
docker push localhost:5000/ubuntu
```

## CI/CD 파이프라인에서의 Docker 역할

```
[CI] Git 소스코드 → 컴파일(빌드) → 테스트 → 패키징
                                              ↓
[CD] Dockerfile로 이미지 생성 → 레지스트리에 push → 배포(운영 서버/Kubernetes 등에서 pull 후 실행)
```
- Docker는 **CI가 끝난 결과물(패키징 산출물)을 이미지로 만들고, 배포하는 CD 단계**에서 핵심적으로 사용됨
- 운영 환경에서는 Docker 외에도 `containerd`, `Podman`, `CRI-O` 등 다양한 컨테이너 런타임과, 이를 관리/스케줄링하는 **Kubernetes**가 함께 쓰이는 경우가 많음

## 핵심 포인트
> 이미지 이름 앞에 레지스트리 주소를 생략하면 기본적으로 Docker Hub를 사용한다. 사설 레지스트리(로컬, Harbor, ECR 등)를 쓰려면 `tag`로 주소를 명시한 뒤 `push`/`pull` 해야 하며, 이 흐름이 CI/CD 파이프라인의 배포(CD) 단계에서 그대로 활용된다.
