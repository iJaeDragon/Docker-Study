# Dockerfile 명령어 & 빌드

## Dockerfile이란?
- 이미지를 생성하기 위한 전용 언어(DSL, Domain Specific Language)로 작성하는 파일
- 각 명령어 단위로 **레이어(layer)**가 구성되어 이미지가 만들어짐

## Dockerfile 주요 명령어

| 명령어 | 설명 |
|---|---|
| `FROM` | **베이스 이미지** 지정 (필수, 가장 첫 줄). 이 이미지를 기반으로 나머지 작업이 쌓임 |
| `RUN` | 이미지 빌드 과정에서 실행할 명령어 (프로그램 설치, 계정 생성 등). 실행할 때마다 새로운 레이어 생성 |
| `COPY` | 호스트 PC의 파일/디렉토리를 이미지 내부로 복사 (순수 파일 복사만 가능) |
| `ADD` | `COPY`와 유사하지만, **압축 파일 자동 해제** 및 **URL에서 다운로드해서 복사**하는 기능도 지원. 특별한 이유 없으면 `COPY` 사용 권장 |
| `WORKDIR` | 컨테이너 내부에서 작업할 **기본 디렉토리** 지정 |
| `ENTRYPOINT` | 컨테이너 실행 시 **최초로 실행될 프로그램** 지정. 이후 **오버라이드(변경) 불가** |
| `CMD` | 컨테이너 실행 시 최초로 실행될 프로그램 지정. `ENTRYPOINT`와 달리 실행 시점에 **오버라이드 가능** |
| `ENV` | 컨테이너에서 사용할 **환경 변수** 지정 |
| `EXPOSE` | 컨테이너가 사용하는 **포트를 외부에 개방**한다고 명시 (문서화 목적, 실제 포트 연결은 `-p`로 별도 처리) |

> 이번 강의에서는 특히 `FROM`, `RUN`, `COPY`, `CMD`를 핵심 명령어로 강조

## 실습: 첫 Dockerfile 빌드

### Dockerfile 작성
```dockerfile
FROM ubuntu:16.04
```
- `FROM`절만 작성 → 별도 추가 작업 없이 베이스 이미지 그대로를 사용하는 가장 단순한 형태
- 베이스 이미지는 Docker Hub의 **Official(공식) 이미지** 사용 권장 (출처 불분명한 이미지는 악성 데이터 포함 위험)

### 빌드 명령어
```
docker build -t firstimage:0.1 -f Dockerfile .
```
| 옵션 | 설명 |
|---|---|
| `-t`, `--tag` | 생성할 이미지의 이름:태그 지정 (예: `firstimage:0.1`) |
| `-f` | 사용할 Dockerfile 경로/파일명 명시 (파일명이 기본값 `Dockerfile`이고 현재 디렉토리라면 생략 가능) |
| `.` (마지막 인자) | 빌드 컨텍스트 = 현재 디렉토리 (이 안에서 Dockerfile을 찾음) |

- 베이스 이미지가 이미 로컬에 있으면 다운로드 없이 빠르게 빌드 완료

### 생성된 이미지 확인
```
docker images | grep first        (Windows: findstr)
docker images | grep [이미지ID]
```

### 만든 이미지로 컨테이너 실행
```
docker run firstimage:0.1
```
- `FROM`절만 있는 이미지는 실행할 프로세스가 없어서 **즉시 종료**됨 (`docker ps`에 안 보임)

```
docker run -it firstimage:0.1 bash
```
- `-it` + `bash`로 실행하면 컨테이너 내부 쉘로 접속되어 **Running 상태 유지**
- `exit`로 나가면 프로세스 종료와 함께 컨테이너도 종료

## 핵심 포인트
> Dockerfile은 `FROM`(베이스) → `RUN`/`COPY`(설치·파일 복사) → `WORKDIR`(작업 경로) → `CMD`/`ENTRYPOINT`(실행 프로그램) 순으로 구성하며, `docker build -t 이름:태그 .`로 빌드해서 나만의 이미지를 만든다. `FROM`만 있는 이미지는 실행할 프로세스가 없어 `run`만으로는 곧바로 종료되므로, 유지하려면 `-it` 등으로 쉘을 실행해야 한다.
