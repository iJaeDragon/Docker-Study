# Docker Hub 업로드 실습 (클라우드 레지스트리)

## 사전 준비
- Docker Hub 계정 필요 (public repository는 무료 계정도 사용 가능, private는 무료 계정 1개로 제한)
- Docker Hub 사이트에서 **Create Repository**로 저장소를 미리 만들어두는 것이 정상적인 순서
  - 단, 저장소가 없는 상태로 `push`해도 자동 생성되긴 함

## 흔한 오류: Access Denied
```
docker push nodejs-demo1:v2.0
# → access denied
```
- 원인: 이미지 이름에 계정명이 없으면 기본적으로 **`library`(Docker 공식 계정)**로 인식됨
- 일반 사용자는 `library` 계정에 업로드할 권한이 없음 → 반드시 **본인 계정명**으로 태그를 바꿔야 함

## 올바른 방법: 계정명을 붙여서 태그 변경 후 push
```
docker tag nodejs-demo1:v2.0 [본인계정명]/nodejs-demo1:v2.0
docker push [본인계정명]/nodejs-demo1:v2.0
```
- 로컬 레지스트리 때는 `localhost:5000/...`였다면, Docker Hub는 **본인 계정명**을 이미지명 앞에 붙임
- 로그인이 안 되어 있으면 `docker login` 실행 후 인증 정보 입력

## latest 태그도 함께 업로드
```
docker tag nodejs-demo1:latest [본인계정명]/nodejs-demo1:latest
docker push [본인계정명]/nodejs-demo1:latest
```
- Docker Hub 저장소 새로고침 시 `v2.0`, `latest` 두 태그 모두 확인 가능
- 이미지 상세 페이지에서 Dockerfile에 있던 `WORKDIR`, `COPY`, `RUN` 등 빌드 과정이 표시됨

## 로컬 이미지 정리 (삭제)
```
docker rmi [이미지ID]
```
- 동일한 이미지 ID를 여러 태그(이름)가 참조하고 있으면 삭제 오류 발생
- 해결 방법 두 가지
  1. 이미지명:태그를 하나씩 정확히 명시해서 개별 삭제
  2. `docker rmi -f [이미지ID]` → **강제 삭제** (연결된 태그들까지 한번에 삭제)

## 삭제 후 다시 다운로드
```
docker pull [본인계정명]/nodejs-demo1:v2.0
```
- 태그를 명시하지 않으면 자동으로 `latest`를 받아오므로, 원하는 버전은 반드시 태그를 명시

## 핵심 포인트
> Docker Hub에 올릴 때는 이미지명 앞에 **본인 계정명**을 반드시 붙여야 한다 (안 붙이면 `library` 계정으로 인식되어 권한 오류 발생). 로컬 레지스트리(`localhost:5000/...`)와 원리는 같고, 앞에 붙는 주소만 다르다.
